Go的单元测试完全依赖标准库`testing`包，无需第三方框架，遵循简单的命名和语法规则，能高效验证函数/方法的正确性，还原生支持性能测试（基准测试），是Go工程化开发的核心环节。

下面从「基础规则→入门示例→进阶技巧→常用命令」逐步讲解，新手也能快速上手。

### 一、单元测试的核心规则（必须遵守）
Go对单元测试的文件、函数命名和签名有严格约定，不遵守则测试框架无法识别：
| 规则项         | 具体要求                                                                 |
|----------------|--------------------------------------------------------------------------|
| 测试文件命名   | 必须以 `_test.go` 结尾（如 `calc_test.go`），与被测代码文件同目录        |
| 测试函数命名   | 必须以 `Test` 开头，后跟大写字母（如 `TestAdd`、`TestMultiply`）          |
| 测试函数签名   | 必须接收唯一参数 `t *testing.T`（不能有返回值）                          |
| 基准测试函数   | 以 `Benchmark` 开头，参数为 `b *testing.B`（性能测试专用）                |
| 运行命令       | 基础：`go test`；详细输出：`go test -v`；仅运行指定测试：`go test -run TestAdd` |

### 二、入门示例：编写第一个单元测试
以一个简单的数学工具函数为例，完整演示“被测代码 + 测试代码 + 运行测试”的流程。

#### 步骤1：编写被测代码（calc.go）
创建`calc.go`，包含要测试的`Add`和`Multiply`函数：
```go
// calc.go 被测代码
package main

// 加法函数
func Add(a, b int) int {
    return a + b
}

// 乘法函数（故意写个错误，演示测试失败）
func Multiply(a, b int) int {
    return a * b + 1 // 错误：多加了1
}
```

#### 步骤2：编写测试代码（calc_test.go）
同目录下创建`calc_test.go`，编写测试用例：
```go
// calc_test.go 测试代码
package main

import "testing" // 导入测试标准库

// 测试Add函数：Test + 被测函数名（首字母大写）
func TestAdd(t *testing.T) {
    // 1. 准备测试数据
    a := 2
    b := 3
    expected := 5 // 预期结果

    // 2. 执行被测函数
    actual := Add(a, b)

    // 3. 断言：验证实际结果是否等于预期
    if actual != expected {
        // t.Error：记录错误但继续执行；t.Fatal：记录错误并终止测试
        t.Errorf("Add(%d, %d) 执行失败：预期%d，实际%d", a, b, expected, actual)
    }
}

// 测试Multiply函数（预期会失败）
func TestMultiply(t *testing.T) {
    a := 2
    b := 3
    expected := 6

    actual := Multiply(a, b)
    if actual != expected {
        t.Errorf("Multiply(%d, %d) 执行失败：预期%d，实际%d", a, b, expected, actual)
    }
}
```

#### 步骤3：运行测试
在终端执行测试命令，查看结果：
```bash
# 基础运行（简洁输出）
go test

# 详细输出（推荐，能看到具体测试用例的执行情况）
go test -v
```

**运行结果**：
```
=== RUN   TestAdd
--- PASS: TestAdd (0.00s)
=== RUN   TestMultiply
    calc_test.go:27: Multiply(2, 3) 执行失败：预期6，实际7
--- FAIL: TestMultiply (0.00s)
FAIL
exit status 1
FAIL    your/package/path    0.001s
```
**结果解释**：
- `=== RUN`：开始执行测试用例；
- `--- PASS`：测试通过；`--- FAIL`：测试失败；
- 失败用例会输出具体的错误信息（`t.Errorf`的内容）；
- 最后`FAIL`表示整个测试包有测试用例未通过。

### 三、进阶技巧：让测试更高效、更全面
#### 1. 测试表（Table-Driven Tests）—— 批量测试多组数据
针对同一个函数，测试多组输入/输出（如边界值、异常值），避免重复写测试代码，是Go官方推荐的写法。

修改`TestAdd`为测试表写法：
```go
func TestAdd(t *testing.T) {
    // 定义测试表：切片存储多组测试用例（输入a、输入b、预期结果）
    testCases := []struct {
        name     string // 用例名称，便于定位失败用例
        a, b     int    // 输入参数
        expected int    // 预期结果
    }{
        {"正数相加", 2, 3, 5},
        {"包含0", 0, 5, 5},
        {"负数相加", -2, -3, -5},
        {"正负相加", -2, 3, 1},
    }

    // 遍历测试表，执行每个用例
    for _, tc := range testCases {
        // t.Run：子测试，每个用例作为独立子测试运行
        t.Run(tc.name, func(t *testing.T) {
            actual := Add(tc.a, tc.b)
            if actual != tc.expected {
                t.Errorf("用例[%s]失败：Add(%d, %d) = %d，预期%d", tc.name, tc.a, tc.b, actual, tc.expected)
            }
        })
    }
}
```

运行`go test -v`，输出如下（每个子测试独立显示）：
```
=== RUN   TestAdd
=== RUN   TestAdd/正数相加
=== RUN   TestAdd/包含0
=== RUN   TestAdd/负数相加
=== RUN   TestAdd/正负相加
--- PASS: TestAdd (0.00s)
    --- PASS: TestAdd/正数相加 (0.00s)
    --- PASS: TestAdd/包含0 (0.00s)
    --- PASS: TestAdd/负数相加 (0.00s)
    --- PASS: TestAdd/正负相加 (0.00s)
```
**优势**：
- 新增用例只需在测试表中加一行，代码复用率高；
- 子测试（`t.Run`）能精准定位哪个用例失败，便于调试。

#### 2. 测试覆盖率——验证代码是否被充分测试
Go内置测试覆盖率工具，能统计“被测代码有多少行被测试用例执行到”，帮助发现未覆盖的代码。

**运行命令**：
```bash
# 生成覆盖率报告（简洁版）
go test -cover

# 生成详细覆盖率文件，并用浏览器查看
go test -coverprofile=coverage.out && go tool cover -html=coverage.out
```

**输出示例**：
```
coverage: 100.0% of statements
ok      your/package/path    0.001s
```
- `coverage: 100.0%` 表示所有代码都被测试覆盖；
- `coverage.out` 是覆盖率数据文件，`go tool cover -html` 会生成可视化HTML报告，能直观看到哪些行未被覆盖。

#### 3. 基准测试（性能测试）——测试函数执行效率
基准测试以`Benchmark`开头，参数为`*testing.B`，用于测试函数的执行性能（如每秒能执行多少次）。

在`calc_test.go`中添加基准测试：
```go
// 基准测试Add函数的性能
func BenchmarkAdd(b *testing.B) {
    // b.N：测试框架自动调整的循环次数（保证测试时间足够）
    for i := 0; i < b.N; i++ {
        Add(2, 3) // 要测试的函数
    }
}
```

**运行命令**：
```bash
# 运行基准测试（-bench指定测试函数，.表示所有基准测试）
go test -bench=. -benchmem
```

**输出示例**：
```
goos: darwin
goarch: arm64
pkg: your/package/path
BenchmarkAdd-8    1000000000           0.315 ns/op        0 B/op          0 allocs/op
PASS
ok      your/package/path    0.347s
```
**结果解释**：
- `BenchmarkAdd-8`：`-8`表示使用8个CPU核心；
- `1000000000`：循环执行了10亿次；
- `0.315 ns/op`：每次执行耗时0.315纳秒；
- `0 B/op`：每次执行分配0字节内存；
- `0 allocs/op`：每次执行0次内存分配。

#### 4. 测试夹具（Setup/Teardown）——测试前后的初始化/清理
测试夹具指“测试前初始化资源（如创建临时文件、连接数据库），测试后清理资源”，保证测试环境的独立性。

示例：测试文件操作函数时，创建临时文件（Setup），测试后删除（Teardown）：
```go
// 测试夹具：每个测试函数执行前初始化，执行后清理
func setupTestFile(t *testing.T) string {
    // 创建临时文件
    tmpFile, err := os.CreateTemp("", "test_*.txt")
    if err != nil {
        t.Fatal("创建临时文件失败：", err)
    }
    // 测试结束后删除临时文件（Teardown）
    t.Cleanup(func() {
        os.Remove(tmpFile.Name())
        t.Log("临时文件已清理：", tmpFile.Name())
    })
    // 写入测试数据
    os.WriteFile(tmpFile.Name(), []byte("test content"), 0644)
    return tmpFile.Name()
}

// 测试读取文件函数
func TestReadFile(t *testing.T) {
    // Setup：获取临时文件路径
    filePath := setupTestFile(t)

    // 执行测试逻辑
    content, err := os.ReadFile(filePath)
    if err != nil {
        t.Error("读取文件失败：", err)
    }
    if string(content) != "test content" {
        t.Errorf("读取内容错误：预期'test content'，实际'%s'", string(content))
    }
}
```
**关键**：
- `t.Cleanup`：Go 1.14+新增，注册清理函数，测试函数执行完毕后自动调用；
- 夹具函数（如`setupTestFile`）可复用，避免每个测试用例重复写初始化逻辑。

#### 5. 跳过测试——临时跳过某些用例
在特定条件下（如系统不兼容、依赖缺失），可跳过某个测试用例：
```go
func TestAddOnWindows(t *testing.T) {
    // 判断系统，非Windows则跳过
    if runtime.GOOS != "windows" {
        t.Skip("该测试仅在Windows系统执行")
    }
    // 执行Windows专属测试逻辑
    actual := Add(2, 3)
    if actual != 5 {
        t.Error("Add函数在Windows下执行失败")
    }
}
```

### 四、常用测试命令汇总
| 命令                          | 作用                                                                 |
|-------------------------------|----------------------------------------------------------------------|
| `go test`                     | 运行当前包所有测试用例（简洁输出）                                   |
| `go test -v`                  | 详细输出测试过程（推荐）                                             |
| `go test -run TestAdd`        | 仅运行名称匹配`TestAdd`的测试用例（支持正则，如`TestAdd*`）          |
| `go test -cover`              | 显示测试覆盖率                                                       |
| `go test -coverprofile=out.out` | 生成覆盖率数据文件                                                   |
| `go tool cover -html=out.out` | 将覆盖率文件转为HTML报告，浏览器打开                                 |
| `go test -bench=.`            | 运行所有基准测试                                                     |
| `go test -benchmem`           | 基准测试时显示内存分配信息                                           |
| `go test ./...`               | 运行当前目录及所有子目录的测试用例                                   |

### 五、最佳实践
1. **测试代码与被测代码同目录**：`calc.go`和`calc_test.go`放在同一目录，便于维护；
2. **测试用例要覆盖边界值**：如0、负数、空字符串、最大/最小值等；
3. **测试用例保持独立**：每个测试用例不依赖其他用例的执行结果，避免互相影响；
4. **优先使用测试表**：批量测试多组数据，减少重复代码；
5. **不要忽略错误**：测试中遇到的错误（如文件打开失败）要用`t.Fatal`终止，避免无效测试；
6. **基准测试关注内存分配**：`alloc/op`为0的函数性能通常更优，尽量减少内存分配。

### 总结
1. Go单元测试依赖`testing`包，遵循“`_test.go`文件 + `TestXxx(t *testing.T)`函数”的命名规则；
2. 核心技巧：测试表（批量用例）、子测试（精准定位）、覆盖率（验证充分性）、基准测试（性能）；
3. 常用命令：`go test -v`（详细测试）、`go test -cover`（覆盖率）、`go test -bench=.`（性能）；
4. 测试夹具（`t.Cleanup`）保证测试环境独立，避免脏数据影响结果。

简单记：Go单元测试的核心是“约定优于配置”，无需复杂框架，只需遵守命名规则，结合测试表和覆盖率工具，就能写出高质量的测试用例，保障代码正确性。

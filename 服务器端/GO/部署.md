Go作为编译型语言，部署的核心优势是**编译后生成单一二进制文件，无运行时依赖**，部署流程简洁且跨平台，下面按「部署前准备→核心部署方式→生产级优化」的逻辑，结合实操示例讲解。

### 一、部署前核心准备：编译打包（关键！）
Go项目部署的第一步是将代码编译为目标平台的二进制可执行文件（无需安装Go环境即可运行），重点解决「跨平台编译」和「编译优化」问题。

#### 1. 基础编译（同平台）
如果开发机和生产机是同一系统（如都是Linux amd64），直接编译：
```bash
# 进入项目根目录（含go.mod的目录）
cd /path/to/your/project

# 清理依赖缓存（可选）
go mod tidy

# 编译：-o 指定输出二进制文件名（如myapp）
go build -o myapp main.go

# 验证编译结果（运行二进制）
./myapp
```

#### 2. 交叉编译（跨平台）
开发机（如Mac/Windows）编译生产机（如Linux）的二进制，需设置环境变量指定目标平台/架构：
| 目标系统 | 环境变量（GOOS/GOARCH）| 编译命令示例                          |
|----------|-------------------------|---------------------------------------|
| Linux amd64 | GOOS=linux GOARCH=amd64 | GOOS=linux GOARCH=amd64 go build -o myapp-linux main.go |
| Linux arm64 | GOOS=linux GOARCH=arm64 | GOOS=linux GOARCH=arm64 go build -o myapp-linux-arm main.go |
| Windows amd64 | GOOS=windows GOARCH=amd64 | GOOS=windows GOARCH=amd64 go build -o myapp.exe main.go |
| Mac arm64 | GOOS=darwin GOARCH=arm64 | GOOS=darwin GOARCH=arm64 go build -o myapp-mac main.go |

**示例：Mac编译Linux二进制**
```bash
# 临时设置环境变量（Linux amd64）
export GOOS=linux
export GOARCH=amd64

# 编译（静态编译，避免系统依赖）
CGO_ENABLED=0 go build -ldflags="-s -w" -o myapp-linux main.go

# 解释参数：
# CGO_ENABLED=0：禁用CGO，生成纯静态二进制（无libc依赖）
# -ldflags="-s -w"：去掉调试信息，减小二进制体积（-s去掉符号表，-w去掉DWARF调试信息）
```

#### 3. 编译后验证
```bash
# 查看二进制文件信息（Linux）
file myapp-linux
# 输出示例：myapp-linux: ELF 64-bit LSB executable, x86-64, statically linked, Go BuildID=xxx, not stripped

# 压缩二进制（可选，减小体积）
upx -9 myapp-linux # 需安装upx工具：apt install upx / brew install upx
```

### 二、核心部署方式（从简单到生产级）
#### 方式1：单机部署（最简，适合小项目/测试）
将编译好的二进制上传到生产服务器，直接运行，适合低流量、无高可用要求的场景。

##### 步骤1：上传二进制到服务器
```bash
# 本地用scp上传（替换服务器IP和路径）
scp myapp-linux root@192.168.1.100:/opt/myapp/
```

##### 步骤2：服务器运行
```bash
# 登录服务器
ssh root@192.168.1.100

# 进入目录，赋予执行权限
cd /opt/myapp
chmod +x myapp-linux

# 前台运行（测试，关闭终端则进程终止）
./myapp-linux

# 后台运行（nohup，日志输出到nohup.out）
nohup ./myapp-linux > app.log 2>&1 &

# 查看进程
ps -ef | grep myapp-linux

# 停止进程
kill -9 <进程ID>
```

**关键说明**：
- `nohup`：忽略终端挂断信号，进程后台运行；
- `> app.log 2>&1`：将标准输出/错误输出重定向到日志文件；
- 缺点：进程崩溃后不会自动重启，无统一的进程管理。

#### 方式2：Systemd管理（生产级单机部署）
用Linux系统的`systemd`管理Go进程，实现**开机自启、故障自动重启、日志统一收集**，是单机生产部署的首选。

##### 步骤1：创建systemd服务文件
```bash
# 新建服务文件（命名为myapp.service）
vim /etc/systemd/system/myapp.service
```

写入以下内容（根据实际路径修改）：
```ini
[Unit]
Description=My Go Application  # 服务描述
After=network.target          # 网络启动后再启动

[Service]
Type=simple                   # 简单进程类型
User=root                     # 运行用户（建议用非root用户，如app）
WorkingDirectory=/opt/myapp   # 工作目录
ExecStart=/opt/myapp/myapp-linux  # 启动命令（二进制路径）
Restart=always                # 总是重启（崩溃/退出时）
RestartSec=3                  # 重启间隔3秒
StandardOutput=journal+console # 日志输出到systemd日志
StandardError=journal+console

[Install]
WantedBy=multi-user.target    # 多用户模式下开机自启
```

##### 步骤2：启动并设置开机自启
```bash
# 重新加载systemd配置
systemctl daemon-reload

# 启动服务
systemctl start myapp

# 设置开机自启
systemctl enable myapp

# 查看服务状态
systemctl status myapp

# 查看日志（实时）
journalctl -u myapp -f

# 停止/重启服务
systemctl stop myapp
systemctl restart myapp
```

#### 方式3：Docker容器部署（推荐，环境隔离）
用Docker打包Go应用和运行环境，实现「一次构建，到处运行」，避免环境依赖问题，适合多环境部署、微服务场景。

##### 步骤1：编写Dockerfile（项目根目录）
```dockerfile
# 阶段1：编译（使用官方Go镜像）
FROM golang:1.22-alpine AS builder

# 设置工作目录
WORKDIR /app

# 复制go.mod/go.sum（优先复制，利用缓存）
COPY go.mod go.sum ./

# 下载依赖
RUN go mod tidy

# 复制所有代码
COPY . .

# 交叉编译（静态编译，适配alpine）
RUN CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -ldflags="-s -w" -o myapp main.go

# 阶段2：运行（使用轻量的alpine镜像，减小最终镜像体积）
FROM alpine:3.20

# 安装时区（可选，解决时区问题）
RUN apk add --no-cache tzdata
ENV TZ=Asia/Shanghai

# 设置工作目录
WORKDIR /app

# 从编译阶段复制二进制文件
COPY --from=builder /app/myapp .

# 暴露端口（根据项目实际端口修改）
EXPOSE 8080

# 启动命令
CMD ["./myapp"]
```

##### 步骤2：构建并运行Docker镜像
```bash
# 构建镜像（-t 打标签，如myapp:v1）
docker build -t myapp:v1 .

# 运行容器（-d 后台运行，-p 端口映射，--name 容器名）
docker run -d --name myapp -p 8080:8080 myapp:v1

# 查看容器日志
docker logs -f myapp

# 进入容器（调试）
docker exec -it myapp sh

# 停止/删除容器
docker stop myapp
docker rm myapp
```

##### 进阶：Docker Compose（多服务部署）
如果项目依赖数据库/Redis等，用`docker-compose.yml`管理多服务：
```yaml
version: '3'

services:
  # Go应用服务
  myapp:
    build: .
    ports:
      - "8080:8080"
    depends_on:
      - mysql
      - redis
    environment:
      - MYSQL_HOST=mysql
      - REDIS_HOST=redis
    restart: always

  # MySQL数据库
  mysql:
    image: mysql:8.0
    ports:
      - "3306:3306"
    environment:
      - MYSQL_ROOT_PASSWORD=123456
      - MYSQL_DATABASE=myapp
    volumes:
      - mysql-data:/var/lib/mysql
    restart: always

  # Redis缓存
  redis:
    image: redis:7.0
    ports:
      - "6379:6379"
    volumes:
      - redis-data:/data
    restart: always

volumes:
  mysql-data:
  redis-data:
```

启动所有服务：
```bash
docker-compose up -d
# 查看日志
docker-compose logs -f myapp
# 停止所有服务
docker-compose down
```

#### 方式4：云服务部署（进阶，生产级）
##### 1. 云服务器（ECS/轻量应用服务器）
本质是「远程Linux服务器」，部署流程和上述「Systemd/Docker」一致，只需注意：
- 开放端口：在云服务商控制台（阿里云/腾讯云）配置安全组，开放应用端口（如8080）；
- 数据持久化：将日志/配置文件挂载到云盘，避免容器/实例销毁后数据丢失；
- 域名解析：将域名解析到服务器IP，配置Nginx反向代理（可选，处理HTTPS、负载均衡）。

##### 2. 容器服务（K8s/阿里云ACK/腾讯云TKE）
适合高可用、高并发的生产场景，核心步骤：
1. 将Docker镜像推送到镜像仓库（如阿里云ACR、Docker Hub）；
2. 编写K8s Deployment/Service配置文件，定义Pod数量、端口、重启策略；
3. 部署到K8s集群，通过Service暴露端口（NodePort/LoadBalancer/Ingress）；
4. 配置Ingress处理HTTPS、域名路由，配置HPA（自动扩缩容）。

##### 3. 无服务部署（Serverless）
Go也可部署到云函数（如阿里云FC、腾讯云SCF），适合轻量接口、事件驱动场景：
- 将Go代码打包为zip，上传到云函数平台；
- 配置触发方式（HTTP/定时/事件）；
- 无需管理服务器，按调用量计费。

### 三、部署关键优化（生产环境必做）
1. **配置分离**：
   - 不要将配置（如数据库密码、端口）硬编码到代码，通过环境变量/配置文件（如config.yaml）传入；
   - 生产环境配置和开发环境分离，可通过`-config`参数指定配置文件：`./myapp -config config-prod.yaml`。

2. **日志管理**：
   - 避免日志输出到控制台，写入文件或日志服务（如ELK、阿里云SLS）；
   - 用`zap`/`logrus`等日志库，按级别（Info/Warn/Error）输出，按天切割日志。

3. **进程守护**：
   - 单机用`systemd`，容器用`restart: always`，K8s用`replicas`+`livenessProbe`（存活探针）；
   - 存活探针示例（K8s）：检查应用健康接口，失败则重启Pod。

4. **HTTPS配置**：
   - 用Nginx反向代理配置HTTPS（推荐），或在Go代码中直接配置（`http.ListenAndServeTLS`）；
   - 证书从Let's Encrypt免费获取，或云服务商申请。

5. **监控告警**：
   - 接入Prometheus+Grafana监控应用指标（QPS、内存、CPU）；
   - 配置告警规则（如CPU使用率>80%、进程崩溃），通过邮件/钉钉通知。

### 总结
#### 核心部署流程
1. **编译打包**：交叉编译为目标平台的静态二进制（`CGO_ENABLED=0`）；
2. **选择部署方式**：
   - 测试/小项目：单机`nohup`运行；
   - 生产单机：`systemd`管理（开机自启、自动重启）；
   - 多环境/微服务：Docker/Docker Compose；
   - 高可用生产：K8s/云容器服务；
3. **生产优化**：配置分离、日志管理、HTTPS、监控告警。

#### 关键要点
1. Go部署的核心优势是「单一二进制文件，无运行时依赖」，静态编译（`CGO_ENABLED=0`）避免系统库依赖问题；
2. 容器部署是生产环境的首选，解决环境一致性问题；
3. 生产环境必须保证进程高可用（自动重启）、日志可追溯、配置安全（不硬编码敏感信息）。

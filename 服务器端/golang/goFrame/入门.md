## 安装
根据文档进行安装，Windows安装时注意选择安装目录最好是golang安装目录。
==安装后运行`gf`命令如果发现是git相关命令（可能是git fetch），是因为 oh-my-zsh 中配置了 git 插件，导致命令冲突。解决方法是修改 oh-my-zsh 的配置文件`vim ~/.zshrc`，在插件中删除git。==

### 创建项目
使用`gf init xxx -u`创建项目。
==安装后发现脚手架有问题，v1变量找不到，需要在相应文件中手动 import`"项目名/api/hello/v1"` 包。==

### 运行项目
进入项目目录，运行`go run main.go`即可运行项目。

### 升级框架
使用`gf up -a`升级框架。

## 脚手架
### 目录结构
|目录/文件名称|说明|描述|
|--|--|--|
|api|对外接口|对外提供服务的输入/输出数据结构定义。考虑到版本管理需要，往往以 api/xxx/v1... 存在。|
|hack	|工具脚本|存放项目开发工具、脚本等内容。例如，CLI 工具的配置，各种 shell/bat 脚本等文件。|
|internal	|内部逻辑|业务逻辑存放目录。通过 Golang internal 特性对外部隐藏可见性。|
|--cmd|入口指令|命令行管理目录。可以管理维护多个命令行。|
|-- consts|常量定义|项目所有常量定义。|
|-- controller|接口处理|接收/解析用户输入参数的入口/接口层。|
|--    dao|	数据访问|	数据访问对象，这是一层抽象对象，用于和底层数据库交互，仅包含最基础的 CRUD 方法。|
|--    logic|	业务封装|	业务逻辑封装管理，特定的业务逻辑实现和封装。往往是项目中最复杂的部分。|
|--    model|	结构模型|	数据结构管理模块，管理数据实体对象，以及输入与输出数据结构定义。|
|----    do|	领域对象|	用于 dao 数据操作中业务模型与实例模型转换，由工具维护，用户不能修改。|
|----        entity|	数据模型|	数据模型是模型与数据集合的一对一关系，由工具维护，用户不能修改。|
|--    service|	业务接口|	用于业务模块解耦的接口定义层。具体的接口实现在 logic 中进行注入。|
|manifest|	交付清单|	包含程序编译、部署、运行、配置的文件。常见内容如下：|
|--config|	配置管理|	配置文件存放目录。|
|--docker|	镜像文件|	Docker 镜像相关依赖文件，脚本文件等等。|
|--    deploy|	部署文件|	部署相关的文件。默认提供了 Kubernetes 集群化部署的 Yaml 模板，通过 kustomize 管理。|
|--    protobuf|	协议文件|	GRPC 协议时使用的 protobuf 协议定义文件，协议文件编译后生成 go 文件到 api 目录。|
|resource|	静态资源|	静态资源文件。这些文件往往可以通过资源打包/镜像编译的形式注入到发布文件中。|
|go.mod|	依赖管理|	使用 Go Module 包管理的依赖描述文件。|
|main.go|	入口文件|	程序入口文件。|

### 基本开发流程
1. 创建数据库和数据表
2. 配置`hack/config.yaml`中数据库的连接参数。此配置是给gf命令使用的。
3. 使用命令`gf gen dao`自动生成数据访问层代码。`internal`目录下的`dao`和`model`目录中会自动生成代码。
    * internal/dao/xxx.go 引用了 internal/dao/internal 中的文件。此文件可以根据需要进行修改。
    * internal/dao/internal/xxx.go 不需要修改，每次运行命令会重新生成。
    * internal/model 中也生成了数据库模型相关文件，也不需要修改。
4. 在`api`目录下定义CRUD接口。（使用版本号的方式有利于未来接口的兼容性维护，注意使用 package 声明包名时要用对应的版本号。参考 goFrameScaffold）
    1. 在`api`目录下创建对应的版本目录和接口文件，如`api/user/v1/user.go`。
    2. 编写`user.go`文件，package声明为`package v1`，并在其中定义接口。
    3. 根据功能来定义接口。每个接口都有对应的请求体和响应体。命名为`XxxReq`和`XxxRes`。
    **版本号的方式主要用于接口提供给APP等调用，APP老版本用户不更新，则不能直接对接口进行破坏性修改，所以需要使用版本号的方式。如果是提供给web调用，则可以选择不使用版本好，毕竟web始终保持最新的。**
5. 使用命令`gf gen ctrl`生成控制器代码。
    * `api`目录下会生成个聚合了所有api函数的接口文件，如`api/user/user.go`，此文件不需要修改。
    * `internal`目录下的`controller`目录中会自动生成代码，此目录是我们要手动编写的具体实现。
        * [路由对象管理](https://goframe.org/quick/scaffold-api-controller#controller路由对象管理)，用来定义内部使用的数据结构、常量等。
        * [接口实现](https://goframe.org/quick/scaffold-api-implements)，在生成的接口文件中编写具体的实现逻辑。
        **用户访问接口，会进入controller中对应的文件，如`user_v1_create.go`，调用其中生成的Create方法，而我们要修改这个方法来实现具体的业务逻辑。如果业务简单，那么可以直接在Create方法中实现，如果业务逻辑复杂，则应该将逻辑抽离到`internal/logic`目录下的文件中，然后在Create方法中调用（实际上应该尽量分离）。而logic作为业务的实现，其定义又应该在service目录中，所以最后的调用逻辑是这样的：**
        `用户访问接口 -> controller中的Create方法 -> service中定义的接口 -> logic中实现的接口方法。`
        ==详见下面的[logic和service](#logic和service)==

    **api中的路由和controller中的接口是如何关联的：**
    1. 在`api`目录下定义接口时，命名为了`XxxReq`。
    2. 在`internal/controller`目录下创建了控制器文件，其中编写对应接口实现时，其中第二个参数就是第一步定义的`XxxReq`。
    3. 在路由中注册控制器。
    ==goframe会使用**反射**，扫描controller中的公开方法，然后通过第二个参数解析其`g.Meta`中的`path`字段，来确定路由的路径。**而不是通过函数名。**==
6. 添加数据库驱动。根据数据库类型安装对应的驱动，数据库驱动从[社区安装](https://github.com/gogf/gf/tree/master/contrib/drivers)，如MySQL：
    1. 运行`go get github.com/gogf/gf/contrib/drivers/mysql/v2@latest`安装MySQL驱动。
    2. 在`main.go`中添加 import，如`_ "github.com/gogf/gf/contrib/drivers/mysql/v2"`。
7. 修改`manifest/config/config.yaml`中的配置，用于生产环境。此配置是给编译后的二进制文件使用的，如main.exe。
8. 注册路由。在`internal/cmd/cmd.go`中[注册路由](https://goframe.org/quick/scaffold-api-config-and-route#添加路由注册)。
    * 路由的分组可以通过在第4步编写API定义的时候通过`g.Meta`的`path`来区分。
    * 路由注册示例：
    ```go
    // note: 实际上我们可以在 api 中定义 path 时就可以通过 path 来进行分组，而不用上面那种分组方式
    s.Group("/api/v1", func(group *ghttp.RouterGroup) {
        group.Middleware(ghttp.MiddlewareHandlerResponse)
        group.Bind(
            hello.NewV1(),
            user.NewV1(), // 这里是v1版本
        )
    })
    // 可在路由上加上版本号，方便未来接口的兼容性维护
    s.Group("/api/v2", func(group *ghttp.RouterGroup) {
        group.Middleware(ghttp.MiddlewareHandlerResponse)
        group.Bind(
            // api/user/v2 目录中编写接口定义后，通过 gf gen ctrl 命令自动生成
            // 此函数对应的文件是能手动修改的，自动生成时会往文件末尾追加代码，而不会覆盖手动修改的代码
            user.NewV2(), // 这里是v2版本
        )
    })
    ```
9. 使用`gf run main.go`启动应用。（使用 go run main.go也能启动，但是不会监听代码变动自动编译）
    ==出现“应用程序控制策略已阻止此文件”的错误，需要在Windows安全中心关闭“智能应用控制”。==

#### logic和service
**这里可以参考[GoFrame框架入门](https://www.bilibili.com/video/BV1Uu4y1u7kX?vd_source=8220e726dcb3a350fd156cea947bd58b&spm_id_from=333.788.videopod.episodes&p=34)的手写logic和service，就能更深入的理解使用方式。**
==实际上应该是先写 service 定义有哪些接口方法，再在 logic 中实现这些接口方法。而 goframe 的 gf gen service 是通过先写 logic 中实现的方法，它知道了有哪些方法后，再根据这些方法来生成 service 中的接口定义文件。==
我们需要在`internal/logic`目录中实现业务逻辑，然后通过`gf gen service`生成`service`目录中的接口定义文件。如：
1. 在`internal/logic/user/user.go`中编写业务代码，如：
    **（注意注释）**
    ```go
    package user

    import (
        "context"

        v1 "goFrameScaffold/api/user/v1"
        "goFrameScaffold/internal/dao"
        "goFrameScaffold/internal/model/do"
    )

    // 这里必须定义为s开头的私有结构体（小写字母开头）
    // 结构体为空说明没有字段，我们只需要使用它来添加方法
    type sUser struct {
    }

    // 添加用户（这里的注释会同步到service目录中的接口定义文件）
    // 给结构体sUser添加方法
    func (u *sUser) AddUser(ctx context.Context, name string, age uint) (res *v1.CreateRes, err error) {
        insertId, err := dao.User.Ctx(ctx).Data(do.User{
            Name:   name,
            Status: v1.StatusOK,
            Age:    age,
        }).InsertAndGetId()
        if err != nil {
            return nil, err
        }
        res = &v1.CreateRes{
            Id: insertId,
        }
        return
    }
    ```
    ==一定要注意使用s开头定义结构体，否则无法正常生成service目录中的接口定义文件。==
2. 运行`gf gen service`生成接口定义文件，此时在`internal/service/user.go`中会生成一个接口定义文件，此文件不需要修改。
    此文件中会有一个`RegisterUser`方法。
3. 在`internal/logic/user/user.go`中将结构体实例注册到`service`包中，如：
    ```go
    ...
    type sUser struct {
    }

    // init 初始化时注册sUser实例到service包中
    func init() {
        // sUser{}创建实例，然后通过&地址符获取实例的指针传入RegisterUser方法
        service.RegisterUser(&sUser{})
    }
    ...
    ```
4. 在`controller`中调用service包中的接口来实现业务逻辑，如：
    ```go
    package user

    import (
        "context"

        v1 "goFrameScaffold/api/user/v1"
        "goFrameScaffold/internal/service"
    )

    func (c *ControllerV1) Create(ctx context.Context, req *v1.CreateReq) (res *v1.CreateRes, err error) {
        // 调用 service 层的 AddUser 方法添加用户
        res, err = service.User().AddUser(ctx, req.Name, req.Age)
        if err != nil {
            return nil, err
        }
        return
    }

    ```

#### 总结
| 步骤 | 描述 |
|------|------|
| 1. 创建数据库和数据表 | 准备项目所需的数据存储结构。 |
| 2. 配置数据库连接 | 编辑 `hack/config.yaml` 设置数据库参数（用于 gf 命令）。 |
| 3. 生成数据访问层 | 运行 `gf gen dao` 自动生成 `internal/dao` 和 `internal/model` 代码（dao 可修改，internal 和 model 勿改）。 |
| 4. 定义 API 接口 | 在 `api` 目录下按版本定义 CRUD 接口（含请求/响应体，如 `XxxReq`/`XxxRes`）。 |
| 5. 生成控制器代码 | 运行 `gf gen ctrl` 生成 `internal/controller` 代码（手动实现业务逻辑，分离到 logic/service）。 |
| 6. 实现业务逻辑 | 在 `internal/logic` 目录中编写具体业务代码（如 `user.go`），封装复杂逻辑。 |
| 7. 生成服务接口 | 运行 `gf gen service` 生成 `internal/service` 目录中的接口定义文件（logic 实现 service 接口）。 |
| 8. 添加数据库驱动 | 安装驱动（如 MySQL: `go get github.com/gogf/gf/contrib/drivers/mysql/v2@latest`），并在 `main.go` 中 import。 |
| 9. 配置生产环境 | 修改 `manifest/config/config.yaml` 用于编译后二进制文件。 |
| 10. 注册路由 | 在 `internal/cmd/cmd.go` 中注册路由（支持分组和版本，如 `/api/v1`）。 |
| 11. 启动应用 | 运行 `gf run main.go` 启动（监听代码变动自动编译）。 |

## 分层架构
* controller：接口层——处理网络请求。
    解析（HTTP）请求参数，调用 logic 中具体的业务逻辑方法，并返回结果。
* logic：业务逻辑层——实现具体的业务逻辑。
    数据库操作应该封装在 dao 中，在 logic 中调用 dao 来完成数据库操作。
    一般小项目中，为了简单，也可以直接在 logic 中实现数据库操作。
* service：服务层——提供统一的接口供 controller 调用。
    使用`go/ast`解析`logic`目录中的文件，提取出所有结构体的方法，生成对应的接口类型定义文件。
* dao：数据访问层——负责与数据库交互。
    提供了数据库访问对象，如`dao.User`，在 dao 中也可以使用自身对象来封装数据库操作给 logic 调用，提高复用性和可维护性。
    `dao/internal`目录中的文件是由工具自动生成的，不需要修改。
* model：数据模型层——定义数据结构。
    `model/entity`是数据库表对应的结构体。（自动生成）
    `model/do`是 data object，把数据表的各个字段类型设置为 any，方便数据库写入/更新等操作。（自动生成）
    项目中的其它自定义数据结构也可以定义在`model`目录中，但是要注意分门别类，方便使用和维护。

### dao 的使用
数据库相关的操作与数据结构放在`dao`与`model`中。我们可以使用dao来获取各个表对应的Model对象，如`dao.Book`得到了book表对应的Model对象。
```go
md := dao.Book.Ctx(ctx) // 获取book表对应的Model对象
cols := dao.Book.Columns() // 获取book表的所有列名，返回一个结构体，结构体中的每个字段都是表中的一个列名，字段值就是列名字符串，如cols.Name == "name"。
md.Where(cols.Id, 13).Data(data).Update() // 通过Model对象进行数据库操作，如更新id为13的数据，data是一个结构体，包含要更新的字段和值。
```

### do 的使用
使用`gf gen dao`时，每个表会生成一个对应的`do`对象，使用`do`对象作为参数传递，将会自动过滤空值：
```go
data := do.Book{
    Name:        "Linux驱动开发入门与实践",
    Price:       0,
    PublishTime: nil,
}

dao.Book.Ctx(ctx).Where("id", 13).Data(data).Update()
```
本来book表中还有其它字段，如果使用普通结构体而不用do，没赋值的字段可能会被更新为0或空字符串等默认值，而不会是NULL，这就导致如deleted_at字段不为NULL的错误。

#### 先看 entity 的问题（关键）

##### entity.User

```go id="d1"
type User struct {
    Id       int
    Username string
    Age      int
}
```

这是：

```text id="d2"
“完整数据结构”
```

#### 如果直接用 entity 更新数据库，会有问题

##### 比如：

你只想更新：

```text id="d3"
用户名
```

##### 代码：

```go id="d4"
entity.User{
    Username: "张三",
}
```

问题来了：

##### Age 没赋值

默认：

```go id="d5"
Age = 0
```

ORM 可能会：

```sql id="d6"
UPDATE user
SET username='张三',
    age=0
```

❌ 把数据误更新了。

#### do 就是解决这个问题

##### do.User

```go id="d7"
type User struct {
    Username interface{}
    Age      interface{}
}
```

👉 现在：

##### 只设置：

```go id="d8"
do.User{
    Username: "张三",
}
```

##### Age 没设置

实际上：

```go id="d9"
Age == nil
```

ORM 会知道：

```text id="d10"
这个字段不要更新
```

#### 所以 do 的核心价值是：

> ❗区分：“字段没传” 和 “字段值为零”

| 类型     | 用途      |
| ------ | ------- |
| entity | 查询结果    |
| do     | 写入/更新参数 |


## 数据校验
数据校验不使用i18n，要返回中文错误信息，可以在 struct tag 中添加信息：
```
NewPassword string `json:"newPassword" v:"required|length:6,16#新密码不能为空|新密码需在6~16之间"  dc:"新密码"`
```
其中`v`标签是验证规则，`#`后面是对应的错误提示，多项验证规则用`|`隔开。

## 数据库操作
### 软删除
数据库表设计时，如果有`deleted_at`字段，则在使用`Delete()`方法删除数据时，gf会将`deleted_at`字段设置为当前时间，而不是物理删除。然后在查询数据时，默认会只查询`deleted_at`为null的数据，即未删除的数据。
如果有`deleted_at`字段，并且需要物理删除/查询已删除的数据等操作，可以使用`Unscoped()`方法，如：
```go
s.Model(ctx).WherePri(in.Id).Unscoped().Delete()
```
上面的语句就会将所在id数据进行物理删除，而不是软删除。
**另外`created_at`和`updated_at`字段也是属于特殊字段，在创建/更新数据时，gf会自动设置这两个字段。**

### 事务处理
在多表操作时（尤其是增删改），为了确保数据的一致性，应该使用事务。
在 gf 中使用事务时，可以通过`db.Transaction`方法来执行一个函数，在这个函数中进行数据库操作，如果函数返回错误，则事务会自动回滚；如果函数执行成功，则事务会自动提交，如：
```go
g.DB().Transaction(ctx, func(ctx context.Context, tx gdb.TX) (err error) {
    // 在这里进行数据库操作，数据库操作时会返回一个 err
    id, err := dao.AdminMember.Ctx(ctx).Data(data).OmitEmptyData().InsertAndGetId()
    if err != nil {
        err = gerror.Wrap(err, "新增用户失败，请稍后重试！")
        return
    }

    // 更新岗位
    if err = service.AdminMemberPost().UpdatePostIds(ctx, id, in.PostIds); err != nil {
        err = gerror.Wrap(err, "新增用户岗位失败，请稍后重试！")
    }

    needLoadSuperAdmin = in.RoleId == s.superAdmin.RoleId
    return
})
```
如果 err 不为 nil，则事务会自动回滚；如果 err 为 nil，则事务会自动提交。
**生成了 DAO 后，DAO 中会生成一个`Transaction`方法，用于执行事务操作。**

### 关联查询
在进行多个表关联查询时，除了使用`LeftJoin`等方法进行关联查询外，还可以使用`With`方法进行关联查询，详见[关联查询](./B站GoFrame框架入门.md#关联查询)。
**注意教程是直接编辑的自动生成的 entity 文件，实际上应该自己新建个 entity 文件，用于关联查询**。

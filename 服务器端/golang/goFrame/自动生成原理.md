
## Service 文件完整生成逻辑拆解

通过查看项目内置的 `genservice` 生成器源码，这是一套基于 Go 标准库 `go/ast` 的代码生成方案，完整流程如下：

---

### 6大核心阶段

#### 阶段1：触发命令
执行命令：
```bash
gf gen service
```
触发整个生成流程的入口。

---

#### 阶段2：AST 语法树解析 (`genservice_ast_parse.go`)
使用 Go 官方标准库的 `go/parser` 把 `internal/logic/` 目录下所有 Go 源文件解析成抽象语法树 AST：

| 解析项 | 作用 |
|---|---|
| ImportSpec | 收集所有导入的包，自动识别包别名 |
| FuncDecl | 收集所有方法，提取：方法接收者类型、方法名、参数列表、返回值列表、方法注释 |
| TypeSpec | 收集结构体信息，识别标记了 `gen:"extend"` 的嵌入结构体 |

关键代码片段：
```go
node, err := parser.ParseFile(fileSet, "", fileContent, parser.ParseComments)
ast.Inspect(node, func(n ast.Node) bool {
    // 遍历所有语法节点
})
```

---

#### 阶段3：计算和整理数据 (`genservice_calculate.go`)
对解析出来的数据进行清洗和整理：
1.  **过滤私有方法**：只保留首字母大写的公开方法
2.  **按接收者分组**：根据接收者结构体名进行分组，比如把所有 `*sAdminMember` 的方法归集到一起
3.  **命名转换**：从 `sAdminMember` → `AdminMember`（去掉前缀 s，大驼峰格式化）
4.  **自动去重引用包**：只保留实际被方法签名用到的 import 包，删除没用到的冗余导入
5.  **处理嵌入结构体的方法继承**：如果结构体嵌入了其他结构体，把嵌入结构体的公开方法也继承进来

---

#### 阶段4：模板渲染生成代码 (`genservice_generate_template.go`)
使用预先定义好的代码模板，把整理好的数据注入进去，生成最终的 service 文件内容。

用到的核心模板（从项目常量中读取）：
```go
// 接口定义模板
type I{StructName} interface {
    {FuncDefinition}
}

// 全局变量模板
var (
    local{StructName} {InterfaceName}
)

// 获取单例方法模板
func {StructName}() {InterfaceName} {
    if local{StructName} == nil {
        panic("implement not found... forgot register?")
    }
    return local{StructName}
}

// 注册方法模板
func Register{StructName}(i {InterfaceName}) {
    local{StructName} = i
}
```

---

#### 阶段5：写入文件
把渲染好的完整代码写入到 `internal/service/` 目录下对应的 `*.go` 文件中。

---

#### 阶段6：在你的业务代码 init() 中自动注册
最后你只需要在 logic 层实现类的 `init()` 函数中调用注册方法：
```go
func init() {
    service.RegisterAdminMember(NewAdminMember())
}
```

整个流程全自动完成，你只需要专注写 `logic/` 目录下的业务实现，接口层的所有重复代码全部由框架自动生成！

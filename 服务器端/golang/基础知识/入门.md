# 环境安装
在 https://go.dev/dl/ 下载对应系统的安装包（如Windows的msi），安装后会在安装目录下的`bin`目录下有`go.exe`文件，此文件是go的编译器。`src`目录下是go的标准库。
安装完成后通过命令`go env`可以确认是否正常安装，并查看go的环境变量（如GOPATH、GOROOT等）。如果不能使用，需要检查环境变量是否配置正确。
然后可以开始编写go的程序了。比如创建`goTest/hello.go`，go文件的扩展名是`.go`：
```go
package main // 每个go程序都必须有一个main包，main函数是程序的入口点

// 导入fmt（format）包，用于打印输出
import "fmt" // go安装目录下的src目录中自带标准库

// main函数是程序的入口点，每个go程序都必须有一个main函数
func main() {
	fmt.Println("Hello, World!")
}
```
## 运行
在`goTest`目录下运行`go run hello.go`，即可运行`hello.go`程序。
另外一种方法是先编译再运行。在`goTest`目录下运行`go build hello.go`，即可在`goTest`目录下生成一个`hello.exe`文件（Windows系统）。然后在`goTest`目录下运行`.\hello.exe`，即可运行此程序。
## vscode环境搭建
安装插件`go`和`code runner`，安装后编写go程序时可以右键点击`Run Code`来运行程序。然后vscode会提示是否安装`gopls`，选择`install all`即可（代理需要开启TUN模式），安装完会提示`[info] All tools successfully installed. You are ready to Go. :)`。
`gopls`是go的语言服务器，用于提供代码补全、跳转定义、查看文档等功能。

如果没有提示安装`gopls`，可以手动安装。`Ctrl+Shift+P`然后输入`Go: Install/Update Tools`，然后点击全选进行安装。
### 代理配置
可通过添加环境变量来配置go的代理服务器：
```bash
$env:GOPROXY="https://goproxy.cn,direct"
```
运行后环境变量会添加`GOPROXY`，值为`https://goproxy.cn,direct`。再运行`go env GOPROXY`，即可查看当前的代理服务器。

    }

        fmt.Println("遍历", x)
    }

        break    // 骗你的
        continue // 不会运行的

    // 对于channel，range返回一个值，
    // array、slice、string、map等其他类型返回一对儿
    for key, value := range map[string]int{"one": 1, "two": 2, "three": 3} {
        // 打印map中的每一个键值对

    }

        fmt.Printf("你是。。 %s\n", name)
    }

    if y := expensiveComputation(); y > x {
        x = y
    }
    // 闭包函数

        return x > 100 // x是上面声明的变量引用

    fmt.Println("两数相加乘二: ",

// c是channel类型，一个并发安全的通信对象。
func inc(i int, c chan int) {
    c <- i + 1 // <-把右边的发送到左边的channel。
}

// 我们将用inc函数来并发地增加一些数字。
func learnConcurrency() {
    // 用make来声明一个slice，make会分配和初始化slice，map和channel。
    c := make(chan int)
    // 用go关键字开始三个并发的goroutine，如果机器支持的话，还可能是并行执行。
    // 三个都被发送到同一个channel。
    go inc(0, c) // go is a statement that starts a new goroutine.
    go inc(10, c)
    go inc(-805, c)
    // 从channel中读取结果并打印。
    // 打印出什么东西是不可预知的。
    fmt.Println(<-c, <-c, <-c) // channel在右边的时候，<-是读操作。

    cs := make(chan string)       // 操作string的channel
    cc := make(chan chan string)  // 操作channel的channel
    go func() { c <- 84 }()       // 开始一个goroutine来发送一个新的数字
    go func() { cs <- "wordy" }() // 发送给cs
    // Select类似于switch，但是每个case包括一个channel操作。
    // 它随机选择一个准备好通讯的case。
    select {
    case i := <-c: // 从channel接收的值可以赋给其他变量
        fmt.Println("这是……", i)
    case <-cs: // 或者直接丢弃
        fmt.Println("这是个字符串！")
    case <-cc: // 空的，还没作好通讯的准备
        fmt.Println("别瞎想")
    }
    // 上面c或者cs的值被取到，其中一个goroutine结束，另外一个一直阻塞。

    learnWebProgramming() // Go很适合web编程，我知道你也想学！
}

## 变量
* go支持声明指针类型的变量，和C语言差不多。
```go
var a int // 使用 var 声明变量，不初始化
a = 10 // 赋值
b := 20 // 短变量声明。声明并初始化，自动推导类型为int，无法指定类型
c := int8(127) // 可以通过强转的方式指定类型
a1, a2, a3 := 1, '2', "3" // 声明并赋值多个变量。'2'是rune类型，是int32的别名，所以会输出ASC码对应的数值
const version = "1.0.0" // 常量声明。自动推断类型

// go也支持指针类型
var p *int // 声明一个指向int类型的指针变量p，初始值为nil
age := 18
p = &age // 取变量age的地址，赋值给指针变量p
fmt.Println(p) // 输出age的内存地址
fmt.Println(*p) // 输出age的值，使用*解引用指针变量p
```
* 局部变量声明了必须使用，否则编译会报错。全局变量和常量可以只声明而不使用。
* 全局变量不能使用`:=`（短变量声明）声明，`:=`只能在函数内部使用。因为`:=`使用自动推导变量类型，全局变量自动推导会导致编译器的一些问题，所以不支持。

### 输出
主要使用`fmt`包中的函数进行输出。常用的函数有：
* `fmt.Println()`：输出字符串并换行。
    `fmt.Println("hello world", 100)` 输出 `hello world 100 \n`
* `fmt.Print()`：输出字符串不换行。
    `fmt.Print("hello world", 100)` 输出 `hello world 100`
* `fmt.Printf()`：格式化输出字符串。
    类似C语言的`printf()`函数。常用的格式化动词有：
    * `%d`：十进制整数
        `fmt.Printf("%d", 100)` 输出 `100`
    * `%f`：浮点数
        `fmt.Printf("%f", 3.14)` 输出 `3.140000`
    * `%s`：字符串
        `fmt.Printf("%s", "hello")` 输出 `hello`
    * `%v`：值的默认格式
        `fmt.Printf("%v", user)` 输出 `{1 张三}`
    * `%#v`：值的Go语法表示
        `fmt.Printf("%#v", user)` 输出 `main.User{ID:1, Name:"张三"}`
    * `%T`：值的类型
        `fmt.Printf("%T", user)` 输出 `main.User`
    * `%p`：指针指向的内存地址
        `fmt.Printf("%p", p)` 输出 `0xc000014098`

## 切片（slice）
可以动态伸缩的数组。每次扩容通常会让容量增加一倍，扩容时的性能较差（大多数情况不影响）。
```go
/**
* 基础切片操作
* 使用 append() 会导致数组扩容，通常每次扩容长度增加一倍
* 扩容时的性能较差，因此高性能操作时可能需要注意，一般问题不大
*/
var list []string // 声明一个字符串切片，初始为nil（不能给长度，有长度就是数组了）
list = append(list, "hepeng") // 追加元素到切片
list = append(list, "tirion") // 追加多个元素到切片
list = append(list, "roc")
l := len(list) // 3


/**
* 使用make()函数创建指定长度和容量的切片
*/
// 使用make()函数创建一个切片，参数为类型、长度、容量。长度是已初始化的元素数量，容量是底层数组的长度。
s1 := make([]int, 3, 5) 
l1 := len(s1) // 3
c1 := cap(s1) // 5 容量


/**
* 数组转换为切片
*/
a := [3]int{1, 2, 3} // 声明数组
s := a[:] // 转换为切片，s的长度和容量都是3
s1 := a[0:2]               // 将数组 0-2 之间的元素转换为切片，长度为2，容量为3
s2 := a[1:]                // 将数组 1-末尾 之间的元素转换为切片，长度为2，容量为2
s3 := a[2:3]               // 将数组 2-3 之间的元素转换为切片，长度为1，容量为1
// 以上容量是数组的长度减去切片的起始索引


/**
* 切片的操作
*/
sort.Ints(s) // 对切片进行排序（不能对数组使用）。升序排序。
sort.Sort(sort.Reverse(sort.IntSlice(s))) // 降序排序。

bs := []byte("a slice") // 使用[]byte()将字符串转换为字节切片
```
错误用法：
```go
var a [2]int // [2] 这里加了长度就是数组
a[0] = 100
a[1] = 200
a = append(a, 300) // 数组不支持append()添加元素
```
### make()函数
使用`make([]T, len, cap)`函数创建一个切片，参数为类型、长度、容量。长度是已初始化的元素数量，容量是底层数组的长度。
长度：初始时可直接访问的元素数量。append()添加元素后，长度会增加。
容量：可选参数。底层数组的长度，即可以通过append()添加的元素数量。当达到容量上线时，再使用append()添加元素，会触发扩容，底层数组的容量会翻倍，因此性能较差。

## map
map 是一种无序的键值对集合，也被称为关联数组或哈希表。每个键都是唯一的，用于快速查找对应的值。
类似TS的对象。
```go
// 声明一个map，key为string，value为int
var m map[string]int = map[string]int{
    "a": 1,
    "b": 2,
    "c": 0,
}
vc, okc := m["c"] // map中存在c字段，值为0，vc为0；okc表示是否存在c字段，所以okc为true
vd, okd := m["d"] // map中不存在d字段，值为0，vd为0；okd表示是否存在d字段，所以okd为false
m["a"] = 10       // 修改值
m["d"] = 100      // 添加字段d
delete(m, "b")    // 删除b字段

var m1 = map[string]int{} // 创建map时必须赋初始值，这样写就赋值了空map
// var m6 map[string]int // 声明map不赋值，值为nil
// m6["a"] = 100 // 不能对nil进行map的操作

var m2 = make(map[string]int) // 使用 make 创建一个空的map
m2["a"] = 100

var m3 = map[string]int{ // 自动推断类型的map
    "a": 100,
    "b": 200,
}
fmt.Println(m, vc, vd, okc, okd)
fmt.Println(m1, m2, m3)
```

## 函数
函数的特性和JS很像。
* 函数里不能创建具名函数，但可以创建匿名函数（匿名函数可赋值给变量）。
* map的值可以是函数，就像JS的对象一样。
* 函数返回函数进行链式调用也很像JS。`add(1)(2)`
* 也有类似JS的闭包。
```go
// 参数类型不同，分别写类型
func setName(id int, name string) {
    fmt.Println(id + "的姓名为：" + name)
}


// 两个参数都是int类型可以简写，返回值也是int类型
func add(a, b int) int {
    return a + b
}


// 可变参数函数，参数数量可以是0个或多个。nums是个切片
func adds(nums ...int) int {
    sum := 0
    // 使用 _ 占位不用的变量
    for _, num := range nums {
        sum += num
    }
    return sum
}
// 调用可变参数函数
fmt.Println(adds(1, 2, 3)) // 输出6


// 返回多个值的函数
func returnName() (string, int) {
    return "hepeng", 28
}
// 调用返回多个值的函数
name, age := returnName()
fmt.Println(name, age) // 输出hepeng 28


// 命名返回值函数：返回类型中声明变量名，会自动返回这些变量
func returnName2() (name string, age int) { // 声明返回值变量名
    name = "hepeng" // 不能使用 := 再次创建 name 变量！！！
    age = 28
    return // 可以省略返回值，默认返回 name, age
}
// 调用命名返回值函数
name, age := returnName2()
fmt.Println(name, age) // 输出hepeng 28
```
### 匿名函数
匿名函数是没有函数名的函数，通常用于在需要函数作为参数的场景，如回调函数、闭包等。
```go
// 定义一个匿名函数，赋值给变量 add
add := func(a, b int) int { // func 后没有函数名
    return a + b
}
// 调用匿名函数
fmt.Println(add(1, 2)) // 输出3


// 函数中定义匿名函数（不能定义具名函数）
func main() {
    // 定义一个匿名函数，直接调用
    func(a, b int) {
        fmt.Println(a + b)
    }(1, 2) // 输出3

    add := func(a, b int) int { // 定义一个匿名函数，赋值给变量 add
        return a + b
    }
    fmt.Println(add(1, 2)) // 调用匿名函数
}
```
### 高阶函数
* 高阶函数是指**接受其他函数作为参数**或**返回函数**的函数。
```go
// 定义一个高阶函数，接受一个函数作为参数
func apply(a, b int, op func(int, int) int) int {
    return op(a, b)
}
// 定义一个加法函数
func add(a, b int) int {
    return a + b
}
// 调用高阶函数，传入加法函数
fmt.Println(apply(1, 2, add)) // 输出3
```

### 值传递和引用传递
这一块类似C语言的指针传递。
```go
// 值传递
func changeValue(a int) {
    a = 100
}

// 引用传递
func changeRef(b *int) { // 使用*接收地址
    *b = 200 // 使用*解引用，修改原变量值
}
// 调用值传递函数
a := 10
changeValue(a)
fmt.Println(a) // 输出10，未改变

// 调用引用传递函数
b := 20
changeRef(&b) // 使用&获取变量的内存地址
fmt.Println(b) // 输出20，已改变
```

### init函数
* 每个包可以有一个`init`函数，`init`函数在包被导入时自动调用，用于初始化包级别的变量或执行其他必要的操作。
* `init`函数没有参数和返回值，不能被直接调用，只能在导入包时自动执行。
* 一个包可以有多个`init`函数，它们会按照声明的顺序依次执行。
```go
// user/init.go
package user // 声明user包
// init函数，在包被导入时自动调用
func init() {
    fmt.Println("user包初始化")
}
func init() { // 可以有多个init函数
    fmt.Println("user包初始化2")
}
```

### defer函数
* `defer`函数是在当前函数执行完毕后，**按照声明顺序逆序执行**。
* 通常用于**资源释放**、**关闭文件**、**解锁**等操作，确保在函数返回前执行。
```go
// 定义一个函数，包含 defer 语句
func example() {
    fmt.Println("开始")
    defer fmt.Println("最后")
    defer fmt.Println("中间") // 后面的defer先执行
    fmt.Println("结束")
}
// 调用函数
example()
// 输出：
// 开始
// 结束
// 中间
// 最后
```

## 结构体
go的结构体也是连续内存。
* 结构体是一种自定义数据类型，用于表示**相关数据的集合**。
* 结构体定义了**字段（field）**，每个字段都有一个**名称**和一个**类型**。
* 结构体可以**包含其他结构体**，形成**嵌套结构体**。
* 结构体可以**包含方法**，用于操作结构体的字段。
```go
// 定义一个结构体
type User struct {
    Name string
    Age  int
}
// 创建一个结构体实例
user := User{Name: "hepeng", Age: 28}
// 访问结构体字段
fmt.Println(user.Name) // 输出hepeng
fmt.Println(user.Age)  // 输出28


// 定义一个结构体方法：接收结构体指针（固定写法），就给结构体添加了方法
func (u *User) GetInfo() string {
    return u.Name + " | " + strconv.Itoa(u.Age)
}
// 调用结构体方法：上面给结构体添加了方法，就能通过结构体调用
fmt.Println(user.GetInfo()) // 输出hepeng | 28


// 组合（结构体嵌套）
type Student struct {
    User // 嵌套User结构体
    ID int
}
// 创建一个结构体实例
student := Student{
    User: User{Name: "hepeng", Age: 28},
    ID: 1001,
}
// 访问结构体字段
fmt.Println(student.Name) // 输出hepeng（嵌套实际上是组合的形式，所以可以直接访问）
fmt.Println(student.ID)   // 输出1001
// 如果组合的结构体中有相同的字段，访问时需要指定结构体名
fmt.Println(student.User.Name) // 指定 User 结构体中的 Name 字段

// 具名字段的结构体
type Teacher struct {
    u User // 使用具名字段来接收结构体
    Subject string
}
teacher := Teacher{
    u: User{Name: "hepeng", Age: 28},
    Subject: "Math",
}
fmt.Println(teacher.u.Name) // 必须使用.u来访问
```
### 方法
函数名前面加括号是 Go 实现面向对象风格 “方法（Method）” 的核心语法，这个括号被称为方法接收者（Receiver）。功能是给**结构体/自定义类型**添加方法。
1. 函数名前的括号是方法接收者声明，语法格式：`func (接收者变量 接收者类型) 方法名(参数) 返回值 { ... }`；
2. 括号内的 “接收者类型”**只能是自定义类型**（结构体 / 基本类型别名）或其指针类型，不能是内置基本类型（如 int）、接口、函数类型等
### 结构体指针
==接收结构体的函数会将结构体的副本传递给函数，而不是结构体的引用。因此，在函数中修改结构体的字段，不会影响到传入的结构体实例。这和JS的引用传递是不同的。使用结构体指针才能在函数中修改结构体的字段。==
* 结构体指针是指向结构体的内存地址的指针，用于在函数中传递结构体实例的引用。
* 定义结构体指针时，需要使用`*`运算符，如`*User`表示指向`User`结构体的指针。
* 访问结构体指针的字段时，需要使用`(*指针名).字段名`的语法，如`(*u).Name`表示访问`u`指针指向的`User`结构体的`Name`字段。
* 也可以使用`指针名.字段名`的语法，如`u.Name`表示访问`u`指针指向的`User`结构体的`Name`字段。

以下3个打印的地址是不同的，说明接收结构体的函数会将结构体的副本传递给函数，而不是结构体的引用：
```go
type Student struct {
	Name string
	Age  int
}

func (s Student) setName() {
	fmt.Printf("b, %p\n", &s)
	s.Name = "bbb"
}

func add(s Student) {
	fmt.Printf("s, %p\n", &s)
}

func main() {
	student := Student{
		Name: "aaa",
		Age:  28,
	}
	fmt.Printf("a, %p\n", &student)
	student.setName()
	add(student)
}
```
使用结构体指针引用传递：
```go
type Student struct {
	Name string
	Age  int
}
// 要修改结构体中的字段需要接收结构体指针
func (s *Student) setName() {
	s.Name = "bbb"
}

func main() {
	student := Student{
		Name: "aaa",
		Age:  28,
	}
	student.setName() // 调用时 setName 方法接收到的是 student 结构体的指针
	fmt.Println(student.Name)
}
```

### 结构体标签
结构体标签（struct tag）是结构体字段的元数据，用于在运行时反射（reflection）和序列化（serialization）等操作中使用。
* 结构体标签是**键值对**的形式，键和值之间用冒号`:`分隔，键值对之间用空格隔开。
    ==字段必须首字母大写（可导出），否则反射无法读取标签（框架也无法识别）==
* 结构体标签可以定义在结构体字段的**类型**后面，用反引号（`）括起来。
* 结构体标签可以定义在**多个字段**上，每个字段的标签之间用空格隔开。

==很多库和框架会使用**反射**来读取结构体标签，根据标签内容来决定此字段如何处理，因此它们也会有很多自定义的标签规则。==

```go
type Student struct {
    Name string `json:"name"` // 定义 json 标签，指定字段在序列化时的键名为 name
    Age  int    `json:"age,omiempty"`  // 使用 omitempty 标签，当字段为空时，不包含在 JSON 字符串中
    Password string `json:"-"` // 使用 - 表示该字段在序列化时不包含在 JSON 字符串中
}
student := Student{
    Name: "aaa",
    Age:  28,
}
byteData, _ := json.Marshal(student) // 序列化结构体为 JSON 字符串。但是是字节数组，每个字节是一个字符的 ASCII/Unicode 码
fmt.Println(string(byteData)) // 使用 string 函数将字节数组转换为字符串，打印 JSON 字符串
```

# 进阶语法
## 断言
### 类型断言的核心语法
类型断言仅适用于**接口类型变量**（通常是`interface{}`即`any`），核心有两种语法形式：

| 语法形式               | 适用场景                     | 失败行为                |
|------------------------|------------------------------|-------------------------|
| `x.(T)`                | 确定x的底层类型一定是T       | 触发panic               |
| `value, ok := x.(T)`   | 不确定类型，需安全判断       | ok=false，不触发panic   |
| `switch v := x.(type)` | 批量判断多个类型（仅switch中）| -                       |

- `x`：必须是接口类型变量（非接口类型编译直接报错）；
- `T`：目标类型（可以是具体类型如`int`/`string`，或接口类型如`error`）；
- `ok`：布尔值，`true`表示断言成功，`false`表示失败。

### 基础用法示例
#### 1. 不安全断言（无ok，失败panic）
仅适用于**确定类型一定匹配**的场景，失败会直接panic，生产环境慎用：
```go
package main

import "fmt"

func main() {
    // 空接口存储int类型值
    var i any = 100

    // 断言i的底层类型是int（成功）
    num := i.(int)
    fmt.Println("断言后的int值：", num) // 输出：100

    // 断言为string（失败，触发panic）
    // str := i.(string) // panic: interface conversion: interface {} is int, not string
}
```

#### 2. 安全断言（带ok，推荐）
通过`ok`值判断断言是否成功，失败不panic，是生产环境的首选写法：
```go
package main

import "fmt"

func main() {
    // 空接口存储string类型值
    var i any = "hello go"

    // 尝试断言为int（失败）
    num, ok := i.(int)
    if !ok {
        fmt.Println("断言int失败：底层类型不是int")
    } else {
        fmt.Println("断言后的int值：", num)
    }

    // 断言为string（成功）
    str, ok := i.(string)
    if ok {
        fmt.Println("断言后的string值：", str) // 输出：hello go
    } else {
        fmt.Println("断言string失败")
    }
}
```
**输出结果**：
```
断言int失败：底层类型不是int
断言后的string值：hello go
```

### 三、进阶用法：类型分支（switch + type）
当需要批量判断多个类型时，使用`switch v := x.(type)`（`x.(type)`是固定写法，仅能在switch中使用），无需多次写断言，代码更简洁：
```go
package main

import "fmt"

// 通用函数：打印不同类型的值
func printValueType(x any) {
    switch v := x.(type) {
    case int:
        fmt.Printf("类型：int，值：%d\n", v)
    case string:
        fmt.Printf("类型：string，值：%s\n", v)
    case float64:
        fmt.Printf("类型：float64，值：%f\n", v)
    case []int:
        fmt.Printf("类型：[]int，值：%v\n", v)
    case nil:
        fmt.Println("类型：nil")
    default:
        fmt.Printf("不支持的类型：%T，值：%v\n", v, v)
    }
}

func main() {
    printValueType(100)        // 类型：int，值：100
    printValueType("hello")    // 类型：string，值：hello
    printValueType(3.14)       // 类型：float64，值：3.140000
    printValueType([]int{1,2}) // 类型：[]int，值：[1 2]
    printValueType(true)       // 不支持的类型：bool，值：true
    printValueType(nil)        // 类型：nil
}
```

### 四、常见使用场景
#### 1. 处理JSON解析结果（最常用）
标准库`json.Unmarshal`会将JSON数据解析为`map[string]any`，需通过断言提取具体类型值：
```go
package main

import (
    "encoding/json"
    "fmt"
)

func main() {
    jsonStr := `{"name":"张三","age":20,"score":95.5}`
    var data map[string]any

    // 解析JSON到空接口map
    err := json.Unmarshal([]byte(jsonStr), &data)
    if err != nil {
        fmt.Println("JSON解析失败：", err)
        return
    }

    // 断言name为string
    name, ok := data["name"].(string)
    if ok {
        fmt.Println("姓名：", name) // 输出：张三
    }

    // 断言age为float64（JSON数字默认解析为float64）
    age, ok := data["age"].(float64)
    if ok {
        fmt.Println("年龄：", int(age)) // 转为int输出：20
    }

    // 断言score为float64
    score, ok := data["score"].(float64)
    if ok {
        fmt.Println("分数：", score) // 输出：95.5
    }
}
```

#### 2. 遍历多类型切片
切片元素为`any`时，通过断言区分不同类型并处理：
```go
package main

import "fmt"

func main() {
    // 切片存储int、string、bool等不同类型
    slice := []any{10, "hello", 3.14, true, nil}

    for idx, val := range slice {
        switch v := val.(type) {
        case int:
            fmt.Printf("索引%d：int类型，值：%d\n", idx, v)
        case string:
            fmt.Printf("索引%d：string类型，值：%s\n", idx, v)
        case nil:
            fmt.Printf("索引%d：nil\n", idx)
        default:
            fmt.Printf("索引%d：未知类型%T，值：%v\n", idx, v, v)
        }
    }
}
```
**输出结果**：
```
索引0：int类型，值：10
索引1：string类型，值：hello
索引2：未知类型float64，值：3.14
索引3：未知类型bool，值：true
索引4：nil
```

#### 3. 断言为接口类型
断言不仅能转为具体类型，还能转为接口类型（判断是否实现了某个接口）：
```go
package main

import "fmt"

// 定义接口
type Animal interface {
    Speak()
}

// 定义结构体并实现接口
type Dog struct{}
func (d Dog) Speak() { fmt.Println("汪汪汪") }

type Cat struct{}
func (c Cat) Speak() { fmt.Println("喵喵喵") }

func main() {
    var i any = Dog{}

    // 断言为Animal接口（判断是否实现了Animal）
    animal, ok := i.(Animal)
    if ok {
        animal.Speak() // 输出：汪汪汪
    }

    // 批量判断接口实现
    var i2 any = Cat{}
    switch v := i2.(type) {
    case Animal:
        v.Speak() // 输出：喵喵喵
    default:
        fmt.Println("未实现Animal接口")
    }
}
```

### 避坑要点（关键！）
1. **仅接口变量可断言**：非接口类型变量直接断言会编译报错，比如：
   ```go
   var num int = 10
   // num.(string) // 编译错误：cannot type assert num (variable of type int) to type string
   ```

2. **不要忽略ok值**：除非100%确定类型匹配，否则必须用`value, ok := x.(T)`，避免panic。

3. **nil接口的断言逻辑**：
   - 接口变量本身为`nil`（`var i any = nil`）：断言任意类型都返回`ok=false`；
   - 接口变量存储“类型+nil”（`var ptr *int = nil; var i any = ptr`）：断言为`*int`时`ok=true`，但值是`nil`。
   ```go
   package main

   import "fmt"

   func main() {
       // 情况1：接口变量是nil
       var i1 any = nil
       _, ok1 := i1.(int)
       fmt.Println("i1断言int：", ok1) // false

       // 情况2：接口变量存储*int类型的nil
       var ptr *int = nil
       var i2 any = ptr
       v, ok2 := i2.(*int)
       fmt.Println("i2断言*int：", ok2, "值：", v) // true <nil>
   }
   ```

4. **断言失败不改变原变量**：即使断言失败，原接口变量的类型和值不会受影响。


## 自定义类型
创建一个新的类型，与原类型无关了，和原类型的变量进行比较时需要强转后才能比较，可以添加方法。
* 自定义类型是指用户根据自己的需求定义的新类型，它可以是**基本类型**（如`int`、`float64`等）的别名，也可以是**结构体**、**接口**等。
* 自定义类型的主要作用是**增加代码的可读性和可维护性**，同时也可以**添加方法**，提供更方便的使用接口。

```go
// 定义一个自定义类型 Age，它是 int 类型的别名
type Age int
// 给自定义类型 Age 添加一个方法 GetAgeStage
func (a Age) GetAgeStage() int {
	if a < 18 {
		return 0
	} else if a < 30 {
		return 1
	} else if a < 40 {
		return 2
	} else if a < 50 {
		return 3
	} else {
		return 4
	}
}
func main() {
	var age Age = 28 // 变量的类型是 Age
	fmt.Println(age.GetAgeStage()) // 就能调用 Age 类型的方法 GetAgeStage，返回 1
}
```

### 类型别名
只是将原类型的名称换了一个别名，方便阅读，使用起来和原类型完全相同。
* 类型别名是指给**已有的类型**定义一个**新的名称**，新名称与原类型**完全相同**，只是**方便记忆和使用**。
* 类型别名的定义格式为：`type 新类型名 = 原类型名`，如`type MyInt = int`表示定义了一个新类型`MyInt`，它与`int`类型完全相同。
* 类型别名**不能**添加**方法**，只能**使用原类型的方法**。
* 打印类型别名时会打印出**原始类型**的名称。

```go
type MyInt = int
func main() {
	var age MyInt = 28 // 变量的类型是 MyInt
}
```

### 接口
- **接口定义**：一组方法签名的集合，只声明“要做什么”，不定义“怎么做”；
- **实现规则**：Go无需`implements`关键字，只要某个类型实现了接口的**所有方法**，就自动实现该接口（隐式实现）；
- **接口作用**：解耦（抽象与实现分离）、多态（同一接口适配不同类型）、扩展（新增实现不修改原有代码）。

### 接口的基础使用（3步核心流程）
#### 步骤1：定义接口（声明方法签名）
语法：`type 接口名 interface { 方法名(参数) 返回值 }`
```go
package main

import "fmt"

// 定义接口：Animal，包含Speak方法（无参数，返回string）
type Animal interface {
    Speak() string // 仅声明方法签名，无实现
}
```
#### 步骤2：实现接口（类型实现接口的所有方法）
只要自定义类型（如结构体）实现了接口的**所有方法**，就自动实现该接口，无需显式声明：
```go
// 定义Dog结构体，实现Animal接口
type Dog struct {
    Name string
}

// Dog实现Speak方法（匹配Animal接口的方法签名）
func (d Dog) Speak() string {
    return fmt.Sprintf("%s: 汪汪汪", d.Name)
}

// 定义Cat结构体，实现Animal接口
type Cat struct {
    Name string
}

// Cat实现Speak方法（匹配Animal接口的方法签名）
func (c Cat) Speak() string {
    return fmt.Sprintf("%s: 喵喵喵", c.Name)
}
```
#### 步骤3：使用接口（接收接口类型，实现多态）
接口变量可以接收**任意实现了该接口的类型实例**，调用接口方法时会自动执行对应类型的实现：

```go
// 通用函数：接收Animal接口，不关心具体是Dog还是Cat
func MakeSound(a Animal) {
    fmt.Println(a.Speak()) // 多态：传入不同类型，执行不同实现
}

func main() {
    // 实例化Dog和Cat
    dog := Dog{Name: "旺财"}
    cat := Cat{Name: "咪宝"}

    // 传入接口类型参数，实现多态调用
    MakeSound(dog) // 输出：旺财: 汪汪汪
    MakeSound(cat) // 输出：咪宝: 喵喵喵
}
```

#### 接口的核心特性
##### 1. 隐式实现（Go的核心设计）
和Java不同，Go无需`type Dog struct implements Animal`这种显式声明——只要类型的方法签名和接口完全匹配，就自动实现接口。这让代码更简洁，且能实现“非侵入式扩展”（新增接口不修改原有类型代码）。

##### 2. 空接口（interface{}）：接收任意类型
空接口没有任何方法签名，因此**所有类型都自动实现了空接口**，常用于接收“任意类型”的场景（如`fmt.Println`的参数）：
go语言中的any类型就是空接口：`type any = any`
```go
// 空接口示例：接收任意类型的参数
func PrintAnything(v any) {
    fmt.Printf("类型：%T，值：%v\n", v, v)
}

func main() {
    PrintAnything(100)        // 类型：int，值：100
    PrintAnything("hello")    // 类型：string，值：hello
    PrintAnything(Dog{Name: "旺财"}) // 类型：main.Dog，值：{旺财}
}
```

⚠️ 注意：空接口仅能存储任意类型，但无法直接调用该类型的方法——需通过「类型断言」获取具体类型后才能调用。

##### 3. 类型断言（接口转具体类型）
当需要从接口变量中获取“实际的具体类型”时，使用类型断言：`具体类型变量, ok := 接口变量.(具体类型)`

```go
func main() {
    var a Animal = Dog{Name: "旺财"}

    // 类型断言：判断a是否指向Dog类型
    dog, ok := a.(Dog)
    if ok {
        fmt.Println("是Dog类型：", dog.Name) // 输出：是Dog类型： 旺财
    }

    // 类型断言失败（a不是Cat类型）
    cat, ok := a.(Cat)
    if !ok {
        fmt.Println("不是Cat类型") // 输出：不是Cat类型
    }

    // 批量判断类型：type switch
    switch v := a.(type) { // 使用 type 关键字，返回接口变量的具体类型
    case Dog:
        fmt.Printf("Dog: %s\n", v.Name)
    case Cat:
        fmt.Printf("Cat: %s\n", v.Name)
    default:
        fmt.Println("未知类型")
    }
}
```

##### 4. 接口嵌套（组合多个接口）
Go支持接口嵌套，形成“组合接口”——只要类型实现了所有嵌套接口的方法，就实现了组合接口：

```go
// 定义跑的接口
type Runner interface {
    Run() string
}

// 定义跳的接口
type Jumper interface {
    Jump() string
}

// 组合接口：既会跑又会跳
type SportAnimal interface {
    Runner  // 嵌套Runner接口
    Jumper  // 嵌套Jumper接口
    Speak() string // 新增方法
}

// 定义Rabbit，实现SportAnimal的所有方法
type Rabbit struct {
    Name string
}

func (r Rabbit) Run() string {
    return fmt.Sprintf("%s: 蹦蹦跳跳跑", r.Name)
}

func (r Rabbit) Jump() string {
    return fmt.Sprintf("%s: 高高跳", r.Name)
}

func (r Rabbit) Speak() string {
    return fmt.Sprintf("%s: 吱吱吱", r.Name)
}

func main() {
    rabbit := Rabbit{Name: "小白"}
    var sa SportAnimal = rabbit
    fmt.Println(sa.Run())   // 输出：小白: 蹦蹦跳跳跑
    fmt.Println(sa.Jump())  // 输出：小白: 高高跳
    fmt.Println(sa.Speak()) // 输出：小白: 吱吱吱
}
```

##### 5. 接口的nil值陷阱
接口变量的“nil”需要满足：**动态类型 + 动态值** 都为nil。若接口变量指向“值为nil的指针类型”，接口本身不为nil：

```go
type MyError interface {
    Error() string
}

type CustomError struct {
    Msg string
}
// CustomError实现了Error所以实现了MyError接口
func (e *CustomError) Error() string {
    if e == nil {
        return "空错误"
    }
    return e.Msg
}

func main() {
    var err *CustomError = nil
    var e MyError = err // 值为nil的实现了MyError接口的结构体指针赋值给了MyError，但是e不为nil

    if e != nil { // 接口本身不为nil！
        fmt.Println(e.Error()) // 输出：空错误
    }
}
```

## 协程（goroutine）
协程是Go语言的轻量级线程，由Go运行时（runtime）管理，无需手动创建线程，也无需担心线程安全问题。

### 一、goroutine的核心定义
- **本质**：goroutine是Go运行时调度的**轻量级执行单元**，也常被称为“Go协程”；
- **调度**：由Go runtime的M:N调度器管理（M个OS线程对应N个goroutine），而非直接由OS内核调度；
- **开销**：初始栈大小仅2KB（可动态扩容/缩容，最大达GB级），创建/销毁/切换成本远低于OS线程（OS线程栈通常MB级）；
- **并发**：单个Go程序可轻松创建数万个甚至数十万个goroutine，而OS线程通常只能创建数千个（受内存限制）。

### 二、goroutine的关键特性（新手必懂）
| 特性                | 说明                                                                 |
|---------------------|----------------------------------------------------------------------|
| 轻量级              | 初始栈2KB，动态伸缩，创建成本≈几纳秒，OS线程创建成本≈微秒级          |
| 调度高效            | Go runtime的M:N调度（用户态切换），无需陷入内核，切换成本远低于线程  |
| 抢占式调度          | Go 1.14+支持抢占式调度，避免某个goroutine长期占用CPU（如死循环）     |
| 与线程的关系        | 多个goroutine可复用一个OS线程，goroutine阻塞（如IO）时会自动让出线程 |
| 内存安全            | 需通过channel/互斥锁等实现goroutine间通信，避免数据竞争              |
| 启动简单            | 只需在函数调用前加`go`关键字，无需手动管理生命周期                   |

### 三、goroutine的基础使用
#### 1. 启动goroutine（核心语法：`go 函数()`）
只需在函数（或方法）调用前加`go`关键字，即可启动一个goroutine执行该函数：
```go
package main

import (
    "fmt"
    "time"
)

// 定义一个普通函数
func sayHello(name string) {
    for i := 0; i < 3; i++ {
        fmt.Printf("Hello, %s! 第%d次\n", name, i+1)
        time.Sleep(100 * time.Millisecond) // 模拟耗时操作
    }
}

func main() {
    // 启动goroutine1：执行sayHello("goroutine1")
    go sayHello("goroutine1")
    // 启动goroutine2：执行匿名函数
    go func() {
        for i := 0; i < 3; i++ {
            fmt.Printf("Hello, 匿名goroutine! 第%d次\n", i+1)
            time.Sleep(100 * time.Millisecond)
        }
    }()

    // 主线程（main goroutine）等待：否则主线程退出，子goroutine会被强制终止
    time.Sleep(500 * time.Millisecond)
    fmt.Println("主线程结束")
}
```
**输出（顺序不固定，体现并发）**：
```
Hello, goroutine1! 第1次
Hello, 匿名goroutine! 第1次
Hello, goroutine1! 第2次
Hello, 匿名goroutine! 第2次
Hello, goroutine1! 第3次
Hello, 匿名goroutine! 第3次
主线程结束
```

#### 2. 关键注意点：主线程等待
- main函数所在的goroutine是**主线程**，主线程退出时，所有子goroutine会被**强制终止**；
- 上面示例中用`time.Sleep`等待是临时方案，生产环境需用`sync.WaitGroup`/`channel`等优雅等待：
```go
package main

import (
    "fmt"
    "sync"
    "time"
)

// 函数参数中包含一个指向WaitGroup的指针，用于通知主goroutine子goroutine执行完成
func sayHello(name string, wg *sync.WaitGroup) {
    defer wg.Done() // goroutine结束时，通知WaitGroup计数-1
    for i := 0; i < 3; i++ {
        fmt.Printf("Hello, %s! 第%d次\n", name, i+1)
        time.Sleep(100 * time.Millisecond)
    }
}

func main() {
    // 定义一个WaitGroup，用于等待所有goroutine完成
    var wg sync.WaitGroup

    // 启动2个goroutine，WaitGroup计数+2
    wg.Add(2)
    go sayHello("goroutine1", &wg) //每个goroutine执行完成后，WaitGroup计数-1
    go sayHello("goroutine2", &wg)

    // 等待所有goroutine完成（计数归0）
    wg.Wait()
    fmt.Println("所有goroutine执行完毕，主线程结束")
}
```
**WaitGroup实际上就是一个计数器**，用于等待所有goroutine执行完成。
- `Add(delta int)`：增加WaitGroup的计数器值（delta可负）；
- `Done()`：goroutine执行完成时调用，将计数器-1；
- `Wait()`：阻塞当前goroutine，直到计数器归0（所有子goroutine执行完成）。

### 四、goroutine vs 操作系统线程（核心区别）
| 对比维度         | goroutine（Go协程）| 操作系统线程（OS Thread）|
|------------------|---------------------------------------------|---------------------------------------------|
| 调度者           | Go运行时（用户态）| 操作系统内核（内核态）|
| 栈大小           | 初始2KB，动态扩容/缩容（最大GB级）| 固定大小（通常1-8MB），不可动态调整         |
| 创建/切换成本    | 极低（用户态操作，无需陷入内核）| 高（内核态操作，需上下文切换）|
| 并发数量         | 支持数万/数十万（内存占用小）| 仅数千个（受内存限制）|
| 抢占式调度       | Go 1.14+支持（针对长时间运行的goroutine）| 原生支持抢占式调度                         |
| 内存消耗         | 极小（每个goroutine仅占几KB初始内存）| 大（每个线程占MB级内存）|
| 与Go的集成       | 深度集成（channel、select、sync包等）| 需手动管理（如pthread库），无原生通信机制   |

## channel（核心：goroutine间通信）
go的协程不像JS那样使用 await 后可以接收返回值，所以需要channel来实现。
channel是Go语言中用于goroutine间通信的**管道**，支持**同步**和**异步**通信。

### 一、channel的核心定义
- **本质**：类型化的、线程安全的“消息队列”，用于goroutine间传递数据；
- **类型化**：每个channel只能传递指定类型的数据（如`chan int`仅能传int，`chan string`仅能传string）；
- **核心特性**：自带阻塞/同步机制，无需额外加锁即可保证数据传递的原子性；
- **核心作用**：goroutine间通信、同步（控制执行顺序）、限流。

### 二、channel的基础使用（4个核心操作）
#### 1. 创建channel（make关键字）
channel是引用类型，必须通过`make`创建，分为**无缓冲**和**有缓冲**两种：
```go
package main

import "fmt"

func main() {
    // 1. 无缓冲channel：容量=0，发送/接收会立即阻塞（同步通信）
    // 发送方要等接收方接收后才会继续执行；接收方要等发送方发送后才会继续执行。
    ch1 := make(chan int) // 等价于 make(chan int, 0)
    
    // 2. 有缓冲channel：容量=3，发送到缓冲满才阻塞，接收为空才阻塞（异步通信）
    // 发送方发送1个后会存到缓冲区，缓冲区满后发送方阻塞；
    // 接收方接收完缓冲区后，缓冲区空，接收方阻塞。
    ch2 := make(chan string, 3)

    fmt.Printf("ch1类型：%T，容量：%d\n", ch1, cap(ch1)) // chan int，0
    fmt.Printf("ch2类型：%T，容量：%d\n", ch2, cap(ch2)) // chan string，3
}
```

#### 2. 发送数据（`ch <- 数据`）
将数据写入channel，语法：`通道变量 <- 数据`：
```go
ch := make(chan string, 2)
ch <- "hello" // 向channel写入"hello"
ch <- "world" // 向channel写入"world"
// ch <- "go" // 缓冲已满（容量2），继续发送会阻塞
```

#### 3. 接收数据（`<-ch`）
从channel读取数据，有3种写法：
```go
ch := make(chan string, 2)
ch <- "hello"
ch <- "world"

// 写法1：直接接收（若channel关闭且无数据，会拿到类型零值）
msg1 := <-ch
fmt.Println(msg1) // 输出：hello

// 写法2：带状态接收（ok=false表示channel已关闭且无数据）
msg2, ok := <-ch
if ok {
    fmt.Println(msg2) // 输出：world
}

// 写法3：遍历接收（自动退出当channel关闭且无数据）
ch3 := make(chan int, 3)
ch3 <- 1
ch3 <- 2
ch3 <- 3
close(ch3) // 关闭channel（发送方负责关闭）

// 使用for-range循环接收（当channel关闭且无数据自动退出）
for num := range ch3 {
    fmt.Println(num) // 依次输出1、2、3
}
```

#### 4. 关闭channel（`close(ch)`）
- 由**发送方**调用，关闭后无法再发送数据（再发送就会报panic的死锁错误），但仍可接收剩余数据；
- 重复关闭、关闭nil channel会触发panic；
- 无需关闭只读channel，也无需为“用完即弃”的channel专门关闭（GC会自动回收）。

### 三、channel的核心类型（2类关键划分）
#### 1. 按缓冲划分：无缓冲 vs 有缓冲
| 类型       | 特点                                                                 | 适用场景                     |
|------------|----------------------------------------------------------------------|------------------------------|
| 无缓冲chan | 容量=0，发送和接收**必须同时就绪**（同步通信），一方阻塞等待另一方 | goroutine间严格同步（如握手） |
| 有缓冲chan | 容量>0，发送到缓冲满才阻塞，接收为空才阻塞（异步通信）| 生产/消费速率不匹配（如任务队列） |

#### 2. 按方向划分：双向 vs 单向（函数参数约束）
Go支持声明**单向channel**，用于函数参数约束（增强类型安全，避免误操作）：
- `chan<- T`：仅能发送的channel（发送型）；
- `<-chan T`：仅能接收的channel（接收型）；
- 双向chan可隐式转为单向chan，反之不行。

```go
package main

import "fmt"

// 仅接收数据的函数（参数为接收型chan）
func onlyReceive(ch <-chan int) {
    num := <-ch
    fmt.Println("仅接收：", num)
    // ch <- 200 // 编译报错：send to receive-only type <-chan int
}

// 仅发送数据的函数（参数为发送型chan）
func onlySend(ch chan<- int) {
    ch <- 100
    // num := <-ch // 编译报错：receive from send-only type chan<- int
}

func main() {
    ch := make(chan int) // 双向chan
    go onlySend(ch)      // 双向chan隐式转为发送型
    go onlyReceive(ch)   // 双向chan隐式转为接收型
    time.Sleep(1 * time.Second)
}
```

### select与channel（多路复用）
`select`是Go专为channel设计的“多路复用”语法，可同时监听多个channel的发送/接收操作，避免阻塞在单个channel。实现 “多通道**等待**，择一执行”。
* select的每个case必须是channel 的发送 / 接收操作，不能是普通条件（如num > 5）；
* 多个case同时就绪时，Go 会随机选择一个执行（保证公平性）；
* 无就绪的case时，select会阻塞，直到有一个case就绪。
```go
package main

import (
    "fmt"
    "time"
)

func main() {
    // 声明了2个channel
    ch1 := make(chan string)
    ch2 := make(chan string)

    // goroutine1：1秒后发送数据到ch1
    go func() {
        time.Sleep(1 * time.Second)
        ch1 <- "来自ch1的消息"
    }()

    // goroutine2：2秒后发送数据到ch2
    go func() {
        time.Sleep(2 * time.Second)
        ch2 <- "来自ch2的消息"
    }()

    // select监听多个chan，谁先就绪就执行谁
    for i := 0; i < 2; i++ {
        // **select case语句，不是switch**
        // 开始阻塞，直到ch1或ch2有数据就绪，或超时3秒
        select {
        case msg1 := <-ch1:
            fmt.Println("收到：", msg1)
        case msg2 := <-ch2:
            fmt.Println("收到：", msg2)
        // 超时保护（常用手段）
        case <-time.After(3 * time.Second):
            fmt.Println("超时")
        }
    }
}
```
输出（ch1先就绪，先执行）：
```
收到：来自ch1的消息
收到：来自ch2的消息
```

### 五、channel的常见使用场景
1. **goroutine间通信**：替代共享内存，安全传递数据（核心场景）；
2. **goroutine同步**：无缓冲chan实现“握手”，控制执行顺序；
3. **限流**：有缓冲chan作为信号量（如限制并发数）：
   ```go
   // 限制最多3个并发
   sem := make(chan struct{}, 3)
   for i := 0; i < 10; i++ {
       sem <- struct{}{} // 占用信号量，满了阻塞
       go func(n int) {
           defer func() { <-sem }() // 释放信号量
           fmt.Println("执行任务", n)
           time.Sleep(1 * time.Second)
       }(i)
   }
   ```
4. **关闭通知**：用空struct chan（`chan struct{}`）传递“关闭信号”（空struct无内存占用）；
5. **超时控制**：结合`time.After`实现channel操作的超时保护（如上面select示例）。

### 完整示例代码
这个例子中：
- 1个生产者协程：生成1-5的数字并发送到channel，发送完成后关闭channel；
- 2个消费者协程：从channel读取数字并处理，直到channel关闭；
- 主线程：等待所有协程执行完毕，避免提前退出。

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

// 生产者函数：向channel发送数据，发送完成后关闭channel
// 参数：ch（发送型channel）、wg（WaitGroup，用于通知主线程完成）
func producer(ch chan<- int, wg *sync.WaitGroup) {
	// 协程结束时，通知WaitGroup计数-1
	defer wg.Done()

	// 生成1-5的数字，发送到channel
	for i := 1; i <= 5; i++ {
		ch <- i // 发送数据到channel
		fmt.Printf("[生产者] 发送数据：%d\n", i)
		time.Sleep(200 * time.Millisecond) // 模拟生产耗时
	}

	// 所有数据发送完成，关闭channel（生产者负责关闭！）
	close(ch)
	fmt.Println("[生产者] 已关闭channel，生产完成")
}

// 消费者函数：从channel读取数据，直到channel关闭
// 参数：name（消费者名称）、ch（接收型channel）、wg（WaitGroup）
func consumer(name string, ch <-chan int, wg *sync.WaitGroup) {
	defer wg.Done()

	// 方式1：用range遍历channel（推荐），**自动感知channel关闭**
	// range会一直读取，直到channel关闭且无剩余数据
	for num := range ch {
		fmt.Printf("[消费者%s] 接收并处理数据：%d\n", name, num)
		time.Sleep(300 * time.Millisecond) // 模拟消费耗时
	}

	// 方式2：用"数据, ok"判断（等价于range，更底层）
    // **死循环一直获取channel数据，直到channel关闭**
	// for {
	// 	num, ok := <-ch
	// 	if !ok {
	// 		// ok=false表示channel已关闭且无数据
	// 		fmt.Printf("[消费者%s] 检测到channel关闭，消费完成\n", name)
	// 		break
	// 	}
	// 	fmt.Printf("[消费者%s] 接收并处理数据：%d\n", name, num)
	// 	time.Sleep(300 * time.Millisecond)
	// }

	fmt.Printf("[消费者%s] 消费完成，退出\n", name)
}

func main() {
	// 1. 创建有缓冲channel（容量2），减少生产者/消费者的阻塞
	ch := make(chan int, 2)

	// 2. 创建WaitGroup，用于等待所有协程完成
	var wg sync.WaitGroup

	// 3. 启动生产者协程（计数+1）
	wg.Add(1)
	go producer(ch, &wg)

	// 4. 启动2个消费者协程（计数+2）
	wg.Add(2)
	go consumer("A", ch, &wg)
	go consumer("B", ch, &wg)

	// 5. 主线程等待所有协程完成（计数归0）
	wg.Wait()
	fmt.Println("[主线程] 所有协程执行完毕，程序退出")
}
```

### 核心知识点解释
#### 1. 关闭channel的核心原则
- **谁生产，谁关闭**：必须由**发送方（生产者）** 关闭channel，接收方（消费者）永远不要关闭——否则会导致生产者向已关闭的channel发送数据，触发panic。
- **不重复关闭**：close(ch)只能调用一次，重复调用或关闭nil channel都会panic（示例中生产者只在发送完所有数据后调用一次close，避免此问题）。

#### 2. 消费者感知channel关闭的两种方式
- **方式1（推荐）：range遍历**  
  `for num := range ch` 是Go官方推荐的写法，会自动循环读取channel中的数据，直到：
  - channel被关闭；
  - channel中无剩余数据。
  无需手动判断，代码更简洁。

- **方式2：ok值判断**  
  `num, ok := <-ch` 中，`ok`的含义：
  - `ok=true`：成功读取到数据；
  - `ok=false`：channel已关闭且无剩余数据，此时应退出循环。

#### 3. 协程与channel的协作逻辑
- 生产者发送数据到有缓冲channel，缓冲满时会阻塞，缓冲有空位时继续发送；
- 多个消费者会“争抢”channel中的数据（channel是线程安全的，无需额外加锁）；
- 生产者发送完所有数据后关闭channel，消费者遍历完数据后自动退出；
- `sync.WaitGroup`保证主线程不会提前退出，确保所有协程执行完毕。

#### 4. 关键避坑点
- 不要向已关闭的channel发送数据（panic）；
- 不要重复关闭channel（panic）；
- 无需为“用完即弃”的channel专门关闭（GC会自动回收），但在生产者-消费者模型中，关闭channel是消费者感知“数据发送完毕”的关键；
- nil channel的发送/接收会永久阻塞，需避免操作nil channel。

### 总结
1. 生产者协程负责生产数据并**在发送完成后关闭channel**，是通知消费者“数据已发完”的核心方式；
2. 消费者协程通过`range`或`ok值判断`感知channel关闭，优雅退出，无需额外的退出信号；
3. `sync.WaitGroup`用于主线程等待所有协程完成，避免主线程提前终止导致协程被强制杀死；
4. channel的关闭是“单向通知”——关闭后无法发送，但仍可接收剩余数据，保证数据不丢失。


## 线程安全
准确的说是goroutine安全，主要体现在同时启用了多个goroutine，都会操作同一个变量，则会出现问题：
```go
package main

import (
	"fmt"
	"time"
)

func main() {
	var count int = 0 // 共享资源：全局变量count

	// 启动1000个goroutine，每个goroutine给count加10
	for i := 0; i < 1000; i++ {
		go func() {
			for j := 0; j < 10; j++ {
				count++ // 核心问题：多个goroutine同时写count
			}
		}()
	}

	// 等待所有goroutine执行（临时方案，生产环境用WaitGroup）
	time.Sleep(1 * time.Second)
	fmt.Printf("最终count值：%d（预期值：10000）\n", count) // count值不确定
}
```
**为什么会这样？**
`count++`看似是一个操作，实则对应CPU的3条指令：
1. 读取`count`的当前值到寄存器；
2. 寄存器中的值+1；
3. 将新值写回`count`。

多个goroutine的这3条指令会“交错执行”：比如goroutine1读取到`count=10`，还没来得及+1，goroutine2也读取到`count=10`，最终两个goroutine都写回11，导致少加了1。这种“交错执行”就是**数据竞争**，最终导致结果偏小。

### 二、Go中实现线程安全的4种常见方案（附例子）
针对上面的问题，Go提供了多种同步机制来保证线程安全，核心思路是**让并发的写操作“串行化”**（同一时间只有一个goroutine能修改共享资源）。

#### 方案1：互斥锁（sync.Mutex）——最通用的方案
`sync.Mutex`是“互斥锁”，提供`Lock()`（加锁）和`Unlock()`（解锁）方法：加锁后，其他goroutine调用`Lock()`会**阻塞**，直到当前goroutine解锁，从而保证同一时间只有一个goroutine操作共享资源。

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var count int = 0
	var mu sync.Mutex // 定义互斥锁
	var wg sync.WaitGroup // 替代time.Sleep，优雅等待goroutine完成

	// 启动1000个goroutine
	wg.Add(1000)
	for i := 0; i < 1000; i++ {
		go func() {
			defer wg.Done() // goroutine结束时，WaitGroup计数-1
			for j := 0; j < 10; j++ {
				mu.Lock()   // 加锁：独占共享资源
				count++     // 安全修改count
				mu.Unlock() // 解锁：释放共享资源
			}
		}()
	}

	wg.Wait() // 等待所有goroutine完成
	fmt.Printf("最终count值：%d（预期值：10000）\n", count)
}
```

**运行结果（每次都准确）**：
```
最终count值：10000（预期值：10000）
```

**核心注意点**：
- 加锁后必须解锁，建议用`defer mu.Unlock()`（即使函数panic，也能保证解锁，避免死锁）；
- 锁的粒度要“最小化”：只在修改共享资源的代码段加锁，不要把无关逻辑包在锁内（比如上面的`j++`无需加锁），否则会降低并发效率。

#### 方案2：读写锁（sync.RWMutex）——读多写少场景优化
`sync.RWMutex`是“读写锁”，分为读锁（`RLock()`/`RUnlock()`）和写锁（`Lock()`/`Unlock()`）：
- 读锁：多个goroutine可同时加读锁（读操作并发执行）；
- 写锁：同一时间只能有一个goroutine加写锁，且加写锁时会阻塞所有读锁/写锁。

适合“读操作远多于写操作”的场景（比如配置读取、缓存查询），比互斥锁更高效。

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func main() {
	var config = map[string]string{"timeout": "5s"} // 共享配置（读多写少）
	var rwMu sync.RWMutex
	var wg sync.WaitGroup

	// 100个读goroutine（并发读）
	wg.Add(100)
	for i := 0; i < 100; i++ {
		go func(id int) {
			defer wg.Done()
			rwMu.RLock() // 加读锁：多个goroutine可同时读
			fmt.Printf("读goroutine%d：读取timeout=%s\n", id, config["timeout"])
			time.Sleep(10 * time.Millisecond) // 模拟读耗时
			rwMu.RUnlock() // 解读锁
		}(i)
	}

	// 1个写goroutine（独占写）
	wg.Add(1)
	go func() {
		defer wg.Done()
		rwMu.Lock() // 加写锁：阻塞所有读/写操作
		config["timeout"] = "10s"
		fmt.Println("写goroutine：修改timeout=10s")
		time.Sleep(50 * time.Millisecond) // 模拟写耗时
		rwMu.Unlock() // 解写锁
	}()

	wg.Wait()
	fmt.Println("最终config：", config)
}
```

**运行结果（读goroutine并发执行，写goroutine独占执行）**：
```
读goroutine0：读取timeout=5s
读goroutine1：读取timeout=5s
...（大量读goroutine并发输出）
写goroutine：修改timeout=10s
读goroutine99：读取timeout=10s
最终config： map[timeout:10s]
```

#### 方案3：通道（channel）——Go推荐的“通信共享内存”
Go的设计哲学是“不要通过共享内存通信，而通过通信共享内存”：用channel传递数据，而非直接共享变量，天然实现线程安全（channel本身是线程安全的）。

还是以“count累加”为例，用channel实现：

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	ch := make(chan int, 1000) // 缓冲channel，用于传递要累加的值
	var result int = 0
	var wg sync.WaitGroup

	// 生产者：1000个goroutine，每个发送10个1到channel
	wg.Add(1000)
	for i := 0; i < 1000; i++ {
		go func() {
			defer wg.Done()
			for j := 0; j < 10; j++ {
				ch <- 1 // 发送数据到channel（线程安全）
			}
		}()
	}

	go func() {
		wg.Wait()   // 等待所有生产者完成
		close(ch)   // 关闭channel，通知消费者退出
	}()

	// 消费者：从channel读取并累加（串行写）
	for num := range ch {
		result += num
	}

	fmt.Printf("最终result值：%d（预期值：10000）\n", result)
}
```

**运行结果**：
```
最终result值：10000（预期值：10000）
```

**核心逻辑**：
- 多个goroutine向channel发送数据（channel的发送/接收是线程安全的，无需加锁）；
- 只有一个goroutine从channel读取数据并修改`result`，避免了并发写，天然线程安全；
- 这是Go推荐的方式，比锁更符合“通信共享内存”的设计哲学。

#### 方案4：原子操作（sync/atomic）——简单类型的高效同步
`sync/atomic`包提供了针对基本类型（int32/int64/uint32等）的“原子操作”（加、减、赋值、比较交换等），操作由CPU指令级保证原子性，比锁更高效（无上下文切换开销）。

适合“简单数值累加/赋值”的场景（比如计数器、状态标记）。

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

func main() {
	var count int64 = 0 // 注意：原子操作要求用int64/uint64等类型
	var wg sync.WaitGroup

	// 1000个goroutine，每个累加10
	wg.Add(1000)
	for i := 0; i < 1000; i++ {
		go func() {
			defer wg.Done()
			for j := 0; j < 10; j++ {
				atomic.AddInt64(&count, 1) // 原子加1：CPU指令级保证原子性
			}
		}()
	}

	wg.Wait()
	fmt.Printf("最终count值：%d（预期值：10000）\n", count)
}
```

**运行结果**：
```
最终count值：10000（预期值：10000）
```

**核心注意点**：
- 原子操作仅支持有限的基本类型（int32/int64/uint32/uint64/uintptr等），不支持切片、结构体等复杂类型；
- 不要把原子操作和普通操作混用（比如`count++`和`atomic.AddInt64`同时操作`count`），仍会导致数据竞争。

### 三、如何检测数据竞争？
Go提供了官方工具`go run -race`（或`go build -race`），能检测代码中的数据竞争问题，是调试线程安全的必备工具。

比如对第一个“线程不安全”的例子执行：
```bash
go run -race main.go
```

会输出类似如下的**数据竞争警告**：
```

  main.main.func1()

Previous read at 0x00c00012c008 by goroutine 7:
  main.main.func1()

==================
```

## 异常处理
**Go没有try-catch-finally语法**，而是将“预期错误”（如文件读写失败、网络超时）和“非预期致命异常”（如数组越界、空指针解引用）分开处理：
- 对**预期错误**：用`error`接口显式处理（Go的核心错误处理方式）；
- 对**非预期致命错误**：用`panic`触发恐慌，再用`recover`配合`defer`恢复（仅用于兜底，避免程序崩溃）。

这种设计的核心思想是：**让错误处理显式化，避免隐式的异常捕获掩盖问题**，同时区分“可预见的业务错误”和“不可预见的程序错误”。

### 一、核心1：预期错误处理（error接口）
`error`是Go内置的接口（仅包含一个`Error() string`方法），是Go处理“可预见错误”的标准方式，也是日常开发中最常用的异常处理手段。

#### 1. 错误的返回与检查（Go的核心惯例）
Go的函数遵循“**错误优先返回**”（错误作为最后一个返回值），调用函数时必须**显式检查错误是否为nil**（nil表示无错误）。

##### 示例1：基础错误处理（文件读取）
```go
package main

import (
	"errors" // 使用了 errors 包
	"fmt"
	"os"
)

func main() {
	// 读取文件：返回值为([]byte, error)，error最后返回
	content, err := os.ReadFile("test.txt")
	// 显式检查错误：这是Go的强制惯例
	if err != nil { // err不等于nil表示有错误
		// 错误处理：打印、重试、返回等
		fmt.Printf("读取文件失败：%v\n", err)
		return
	}
	// 无错误时处理正常逻辑
	fmt.Printf("文件内容：%s\n", content)
}
```

##### 示例2：自定义错误（业务场景）
```go
package main

import (
	"errors"
	"fmt"
)

// 自定义函数：计算除法，处理除数为0的预期错误
func divide(a, b float64) (float64, error) { // 将错误作为返回值
	// 预期错误：除数为0，返回错误
	if b == 0 {
		// 创建自定义错误
		return 0, errors.New("除数不能为0") // 使用 errors.New 创建自定义错误
	}
	// 无错误：返回结果+nil
	return a / b, nil
}

func main() {
	res, err := divide(10, 0)
	if err != nil {
		fmt.Println("计算失败：", err) // 输出：计算失败：除数不能为0
	} else {
		fmt.Println("计算结果：", res)
	}

	res2, err2 := divide(10, 2)
	if err2 != nil {
		fmt.Println("计算失败：", err2)
	} else {
		fmt.Println("计算结果：", res2) // 输出：计算结果：5
	}
}
```

#### 2. 错误包装与解包（Go 1.13+）
实际开发中，错误会层层传递，需要保留原始错误信息，Go 1.13+通过`fmt.Errorf("%w", 原始错误)`包装错误，再用`errors.Is`/`errors.As`解包。

```go
package main

import (
	"errors"
	"fmt"
)

var ErrDivisorZero = errors.New("除数不能为0") // 定义基础错误

func divide(a, b float64) (float64, error) {
	if b == 0 {
		// 包装错误：添加上下文，保留原始错误
        // **原始错误ErrDivisorZero的错误内容会赋值给%w，并且能用errors.Is等解包出是ErrDivisorZero错误**
		return 0, fmt.Errorf("divide函数执行失败：%w", ErrDivisorZero) // 使用 fmt.Errorf 包装错误
	}
	return a / b, nil
}

func main() {
	res, err := divide(10, 0)
	if err != nil {
		// **解包err错误，能拿到err错误中的原始错误，然后与ErrDivisorZero比较**
		if errors.Is(err, ErrDivisorZero) { // 使用 errors.Is 检查err是否是ErrDivisorZero
			fmt.Println("核心错误：除数为0") // 输出：核心错误：除数为0
		}
		// 打印完整错误信息
		fmt.Println("完整错误：", err) // 输出：完整错误：divide函数执行失败：除数不能为0
		return
	}
	fmt.Println("结果：", res)
}
```

### 二、核心2：非预期致命错误（panic/recover）
`panic`用于触发“不可预见的致命错误”（如数组越界、空指针解引用、手动终止程序），会立即终止当前goroutine的执行；`recover`仅能在`defer`函数中生效，用于“捕获”`panic`，恢复程序执行（避免整个程序崩溃）。

#### 1. panic：触发恐慌
`panic`是内置函数，语法：`panic(任意类型值)`（通常传字符串或error）。
**触发`panic`后，程序会：**
1. 立即停止当前函数的后续代码执行；
2. 执行当前函数中已声明的`defer`函数；
3. 向上传递到调用栈，**直到被`recover`捕获**，或程序崩溃。

##### 示例1：手动触发panic
```go
package main

import "fmt"

func riskyFunc() {
	fmt.Println("执行riskyFunc...")
	// 手动触发panic：模拟致命错误
	panic("发生了致命错误！")
	fmt.Println("这行代码不会执行") // panic后不会执行
}

func main() {
	fmt.Println("程序开始")
	riskyFunc()
    // **没被recover捕获，程序会崩溃**
	fmt.Println("程序结束") // panic未被恢复，这行也不会执行
}
```
**输出（程序崩溃）**：
```
程序开始
执行riskyFunc...
panic: 发生了致命错误！

goroutine 1 [running]:
main.riskyFunc()
        /xxx/main.go:8 +0x45
main.main()
        /xxx/main.go:14 +0x25
exit status 2
```

#### 2. recover：恢复panic
`recover`是内置函数，仅在`defer`函数中调用才有效，返回`panic`传递的值（若没有panic，返回nil）。
核心用法：`defer + recover` 组合，在函数**退出**前捕获panic。

##### 示例2：用recover恢复panic
```go
package main

import (
	"fmt"
)

func riskyFunc() {
	// 必须在panic前声明defer，否则无法恢复
	defer func() {
		// **使用recover捕获panic，返回panic传递的值（若没有panic，返回nil）**
		if err := recover(); err != nil {
			fmt.Printf("捕获到panic：%v\n", err)
			// 可选：处理错误（如记录日志、清理资源）
		}
	}()

	fmt.Println("执行riskyFunc...")
	panic("发生了致命错误！")
	fmt.Println("这行代码不会执行")
}

func main() {
	fmt.Println("程序开始")
	riskyFunc()
	fmt.Println("程序结束") // 被recover恢复，这行会执行
}
```
**输出（程序不崩溃）**：
```
程序开始
执行riskyFunc...
捕获到panic：发生了致命错误！
程序结束
```

#### 3. 典型场景：recover处理未知panic
在HTTP服务、后台任务等场景中，为避免单个请求的panic导致整个服务崩溃，会在入口函数中用`recover`兜底：
```go
package main

import (
	"fmt"
	"net/http"
)

// 处理HTTP请求的函数，可能触发panic
func handler(w http.ResponseWriter, r *http.Request) {
	defer func() {
        // **使用recover兜底**
		if err := recover(); err != nil {
			// 记录日志 + 返回500错误
			fmt.Printf("请求panic：%v\n", err)
			http.Error(w, "服务器内部错误", http.StatusInternalServerError)
		}
	}()

	// 模拟panic：数组越界
	arr := []int{1, 2, 3}
	fmt.Fprintf(w, "数组第5个元素：%d", arr[4]) // 数组越界，触发panic
}

func main() {
	http.HandleFunc("/test", handler)
	fmt.Println("服务启动：http://localhost:8080/test")
	http.ListenAndServe(":8080", nil)
}
```
访问`http://localhost:8080/test`时，会触发数组越界panic，但`recover`会捕获它，返回500错误，服务不会崩溃。

### 三、Go异常处理的关键注意事项
1. **不要滥用panic**：
   - `panic`仅用于“致命、不可恢复的错误”（如数组越界、空指针）；
   - 业务逻辑错误（如参数错误、文件不存在）必须用`error`处理，而非`panic`。
2. **defer的执行时机**：
   - `defer`函数在函数退出前执行（无论正常退出还是panic退出）；
   - 必须在`panic`前声明`defer`，否则`recover`无法捕获panic。
3. **recover的作用域**：
   - `recover`仅能恢复当前goroutine的panic，无法跨goroutine恢复；
   - 若`recover`在非defer函数中调用，返回nil（无效）。
4. **错误处理的最佳实践**：
   - 函数返回错误时，遵循“错误最后返回”的惯例；
   - 调用函数时必须显式检查错误（不要忽略err）；
   - 复杂错误用`fmt.Errorf("%w")`包装，保留原始错误链。

### 总结
1. Go的异常处理分为两层：
   - **error接口**：处理预期的业务错误，显式返回+检查，是Go错误处理的核心；
   - **panic/recover**：处理非预期的致命错误，仅用于兜底，避免程序崩溃；
   ==error不会导致程序崩溃，但是panic如果没有被recover捕获，程序会崩溃。==
2. 核心惯例：“错误显式处理”，拒绝隐式的try-catch，让错误处理逻辑更清晰；
3. 避坑点：不要用panic替代error处理业务错误，recover仅在defer函数中生效。

## 泛型
### 泛型的核心用法（实战示例）
#### 1. 泛型函数（最常用）
泛型函数的语法：`func 函数名[T 约束](参数列表) 返回值 { ... }`  
==TS的泛型T可以不指定类型，但是go的泛型中的T必须指定类型，当然用了泛型正常情况T都是多个类型。==
**示例1：通用求和函数（解决上面的重复代码问题）**
```go
package main

import "fmt"

// 自定义类型约束：Number可以是int/float64/float32
type Number interface {
    int | float64 | float32
}

// 泛型函数：sum接收任意Number类型的切片，返回同类型的和
func sum[T Number](s []T) T {
    var total T // 声明T类型的零值（int=0，float64=0.0）
    for _, v := range s {
        total += v
    }
    return total
}

func main() {
    // 调用泛型函数：编译器自动推导T的类型
    intSlice := []int{1, 2, 3, 4}
    fmt.Println("int切片和：", sum(intSlice)) // 输出：10

    floatSlice := []float64{1.1, 2.2, 3.3}
    fmt.Println("float64切片和：", sum(floatSlice)) // 输出：6.6

    // 显式指定类型（可选，编译器推导不出来时用）
    fmt.Println("显式指定类型：", sum[float32]([]float32{1.0, 2.0})) // 输出：3
}
```

**示例2：通用交换函数（适配任意类型）**
```go
package main

import "fmt"

// 泛型函数：交换两个任意类型的值（用指针修改原变量）
func swap[T any](a, b *T) {
    temp := *a
    *a = *b
    *b = temp
}

func main() {
    // 交换int
    x, y := 10, 20
    swap(&x, &y)
    fmt.Println("x=", x, "y=", y) // 输出：x=20 y=10

    // 交换string
    s1, s2 := "hello", "world"
    swap(&s1, &s2)
    fmt.Println("s1=", s1, "s2=", s2) // 输出：s1=world s2=hello
}
```

#### 2. 泛型结构体（通用数据结构）
泛型结构体的语法：`type 结构体名[T 约束] struct { 字段名 T }`  
最典型的场景是实现“通用数据结构”（如栈、队列、链表），适配任意类型。

**示例：通用栈（Stack）结构体**
```go
package main

import (
    "errors"
    "fmt"
)

// 泛型结构体：Stack支持任意类型的元素
type Stack[T any] struct {
    elements []T // 存储元素的切片，类型为T
}

// 泛型方法：Push入栈（接收者带类型参数[T]）
func (s *Stack[T]) Push(element T) {
    s.elements = append(s.elements, element)
}

// 泛型方法：Pop出栈，返回栈顶元素+错误（栈空时）
func (s *Stack[T]) Pop() (T, error) {
    if len(s.elements) == 0 {
        var zero T // 声明T类型的零值（返回给调用方）
        return zero, errors.New("栈为空")
    }
    // 取最后一个元素
    lastIdx := len(s.elements) - 1
    element := s.elements[lastIdx]
    // 移除最后一个元素
    s.elements = s.elements[:lastIdx]
    return element, nil
}

// 泛型方法：获取栈的长度
func (s *Stack[T]) Len() int {
    return len(s.elements)
}

func main() {
    // 1. 创建int类型的栈
    intStack := &Stack[int]{}
    intStack.Push(10)
    intStack.Push(20)
    fmt.Println("int栈长度：", intStack.Len()) // 输出：2
    val, _ := intStack.Pop()
    fmt.Println("出栈元素：", val) // 输出：20

    // 2. 创建string类型的栈
    strStack := &Stack[string]{}
    strStack.Push("hello")
    strStack.Push("go")
    val2, _ := strStack.Pop()
    fmt.Println("出栈元素：", val2) // 输出：go
}
```

#### 3. 泛型接口（进阶）
泛型接口的语法：`type 接口名[T 约束] interface { 方法签名 }`  
适用于“需要适配多种类型的接口”场景。

**示例：通用格式化接口**
```go
package main

import "fmt"

// 泛型接口：Formatter要求类型有Format()方法，返回T类型
type Formatter[T any] interface {
    Format() T
}

// 实现Formatter接口的Person结构体
type Person struct {
    Name string
    Age  int
}

// Person的Format方法，返回string（适配Formatter[string]）
func (p Person) Format() string {
    return fmt.Sprintf("Name: %s, Age: %d", p.Name, p.Age)
}

// 通用函数：接收Formatter接口，调用Format方法
func PrintFormat[T any](f Formatter[T]) {
    fmt.Println(f.Format())
}

func main() {
    p := Person{Name: "张三", Age: 20}
    PrintFormat[string](p) // 输出：Name: 张三, Age: 20
}
```

### 泛型的关键细节（避坑点）
1. **类型约束的精确性**：
   - 避免滥用`any`：约束越精确，类型安全越高（比如用`Number`约束比`any`好，能避免传入字符串却执行加法）；
   - 约束中的方法：若约束接口包含方法，类型必须实现该方法才能作为类型参数（比如`type Stringer interface { String() string }`，要求类型有String()方法）。

2. **泛型的性能**：
   - 泛型编译时会为不同的类型参数生成具体代码（类似C++模板），运行时无额外开销（仅编译期稍慢）；
   - 日常开发中性能差异可忽略，仅极致性能场景需评估。

3. **不能做的事**：
   - 泛型类型参数不能用于类型断言的左侧（如`v.(T)`，T是类型参数，编译报错）；
   - 不能用泛型类型参数定义数组长度（如`var arr [T]int`，T是类型参数，编译报错）。

### 泛型的使用场景（什么时候用？）
1. **通用数据结构**：栈、队列、链表、缓存等（如上面的Stack示例）；
2. **通用工具函数**：求和、排序、过滤、比较等（如sum、swap示例）；
3. **跨类型的业务逻辑**：比如处理不同类型的配置、序列化/反序列化通用逻辑；


## 文件引用
Go语言文件间的引用核心靠**包（package）** 管理，核心规则是**首字母大写的标识符（函数/结构体/变量等）才会被导出**，可跨文件/包访问，小写仅同包可见。

### 一、同包内文件引用（最简单，无需import）
1. 同一目录下的所有Go文件，**必须声明相同的包名**（建议与目录名一致）；
2. 直接调用同包内**首字母大写**的标识符即可，无需任何导入。

**示例**：`user/`目录下两个文件，同属`user`包
```go
// user/info.go
package user // 声明user包
// 导出函数，首字母大写
func GetName() string {
    return "hepeng"
}
```
```go
// user/age.go
package user // 声明user包
// 直接调用同包的GetName，无需import
func GetUserInfo() string {
    return GetName() + " | 28"
}
```

### 二、同项目不同包引用（需import包的模块路径+包目录）
1. 先在项目根目录执行`go mod init 模块名`（如`go mod init helloWorld`），初始化Go Module，这是包引用的基础；
2. 导入时写 **「模块名+目标包的相对根目录路径」**；
3. 用`包名.标识符`调用，或给包起别名简化调用。

==项目有一个模块名（这里的 helloWorld），这个模块名会存在于 go.mod 中；项目中的目录是一个包，拥有和目录名相同的包名，所有的包引用都基于这个模块名。另外 main 包作为入口有其特殊性。==

**示例**：项目结构如下，`main`包调用`user`包
```
iot-demo/          // 项目根
  go.mod           // 模块名：helloWorld
  main.go          // 包名：main
  user/            // 包名：user
    info.go		   // user 下的 .go 文件必须使用 package user 包名
    age.go
```
运行`go mod init helloWorld`后，`go.mod`中会出现以下这行，表明这个项目的根模块是`helloWorld`
```
module helloWorld
```
```go
// main.go
package main
// 导入user包：模块名 + 包目录
import "helloWorld/user"

func main() {
    // info.go 和 age.go 导出的都可以通过user包名调用
    // 包名.导出标识符
    println(user.GetUserInfo())
    // 给包起别名，避免重名
    import u "helloWorld/user"
    println(u.GetName())
}
```
==项目目录中的`.go`文件使用的包名虽然可以与目录名不同，但是被引入的时候依然是基于目录结构，所以如果包名不使用目录名会导致很多不必要的麻烦。因此强烈要求包名与目录名保持一致。==
==要注意一点：自己项目中的目录名（包名）不要与标准库中的包名冲突。==

### 三、跨模块引用（第三方包/其他项目，先拉取再导入）
1. 用`go get 模块名@版本`拉取第三方模块到本地（如`go get github.com/gin-gonic/gin@v1.9.1`）；
2. 导入时直接写 **「第三方模块名+包目录」**，调用方式与同项目不同包一致。

**示例**：引用官方标准库（无需go get，已内置）+ 第三方包
```go
package main
// 标准库包，直接导入包名即可
import "fmt"
// 第三方包，导入模块名+包目录
import "github.com/gin-gonic/gin"

func main() {
    fmt.Println(user.GetName())
    r := gin.Default() // 第三方包的调用
}
```

### 四、开发必避3个坑
1. **禁止循环引用**：Go不允许包之间互相导入（如A导入B，B又导入A），需抽离公共逻辑为新包；
2. **包名规范**：包名简洁小写，建议与目录名一致（如目录`utils`，包名`utils`），不要用特殊字符；
3. **未使用的导入**：Go编译会报错，可加`_`忽略（仅执行包的init函数，不调用标识符），如`import _ "github.com/go-sql-driver/mysql"`。

### 五、补充：包的init函数（自动执行，无需调用）
每个包可定义一个/多个`init()`函数，**无参数无返回值**，Go会在导入包时**自动执行**，执行顺序：
`包内全局变量初始化` → `init()函数` → 外部调用包的标识符，常用于包的初始化（如加载配置、注册驱动）。
```go
// user/info.go
package user
import "fmt"
// 自动执行
func init() {
    fmt.Println("user包初始化了")
}
```
当要仅使用这个包的init函数时，可以使用`import _ "helloWorld/user"`。

# 高阶语法
## 反射
**反射（Reflection）** 是Go提供的“运行时检查、修改程序自身结构（类型、变量、方法）”的能力，突破了编译期的类型约束，是实现通用框架（如JSON序列化、ORM、配置解析）的核心技术。反射虽强大，但也增加了代码复杂度和运行时开销，需理解其核心法则和使用场景后谨慎使用。

下面从「核心概念→三大法则→实战示例→避坑点」逐步讲解，结合可运行的代码让你吃透反射。

### 一、反射的核心基础
#### 1. 什么是反射？
普通代码中，变量的类型和值在**编译期**就确定了（如`var a int = 10`，编译期已知a是int类型）；而反射允许程序在**运行期**：
- 检查任意变量的类型（比如判断一个`any`变量实际存储的是int还是string）；
- 操作变量的值（比如修改一个`any`变量的底层值）；
- 调用任意对象的方法（比如不知道结构体类型时，调用其方法）。

#### 2. 反射的核心包和类型
Go反射依赖标准库`reflect`包，核心是两个类型：
| 类型               | 作用                                                                 |
|--------------------|----------------------------------------------------------------------|
| `reflect.Type`     | 表示变量的**类型信息**（如int、string、结构体名、字段名、方法签名等） |
| `reflect.Value`    | 表示变量的**值信息**（如取值、修改值、调用方法等）                   |

获取这两个类型的入口函数：
- `reflect.TypeOf(x)`：从变量x获取`reflect.Type`（x会被转为`any`）；
- `reflect.ValueOf(x)`：从变量x获取`reflect.Value`（x会被转为`any`）。

#### 3. 反射的三大法则（Go官方定义，必须掌握）
这是理解反射的核心，所有反射操作都遵循这三条规则：
1. **法则1**：从**接口值（interface{}）** 可以反射出反射对象（Type/Value）；
   - Go中所有变量都能隐式转为`any`，反射的入口就是将变量转为接口值，再提取反射对象；
2. **法则2**：从反射对象可以还原回接口值；
   - 反射对象（Type/Value）可通过`Interface()`方法转回`any`，再类型断言还原为原变量；
3. **法则3**：要修改反射对象，其值必须是**可设置的（settable）**；
   - 可设置的核心条件：反射对象必须指向原变量的**可寻址内存**（即指针指向的原值），且变量不是只读副本。

### 二、实战示例：从基础到进阶
#### 示例1：基础用法——获取变量的类型和值（法则1）
最基础的反射场景：检查任意变量的类型、值、种类（Kind）。
```go
package main

import (
	"fmt"
	"reflect"
)

func main() {
	// 测试不同类型的变量
	var a int = 10
	var b string = "hello"
	var c float64 = 3.14
	var d = []int{1, 2, 3}
	var e = struct {
		Name string
		Age  int
	}{"张三", 20}

	// 封装反射检查函数
	checkTypeAndValue := func(x any) {
		// 1. 获取reflect.Type
		t := reflect.TypeOf(x)
		// 2. 获取reflect.Value
		v := reflect.ValueOf(x)

		// 输出核心信息
		fmt.Println("=== 变量信息 ===")
		fmt.Printf("原始值：%v\n", x)
		fmt.Printf("类型（Type）：%s\n", t.Name())       // 类型名（如int、string）
		fmt.Printf("种类（Kind）：%s\n", v.Kind())      // 底层种类（如int、slice、struct）
		fmt.Printf("值（Value）：%v\n", v.Interface()) // 反射值转回接口值
		fmt.Println("-----------------")
	}

	// 测试不同变量
	checkTypeAndValue(a)
	checkTypeAndValue(b)
	checkTypeAndValue(c)
	checkTypeAndValue(d)
	checkTypeAndValue(e)
}
```
**运行结果**：
```
=== 变量信息 ===
原始值：10
类型（Type）：int
种类（Kind）：int
值（Value）：10
-----------------
=== 变量信息 ===
原始值：hello
类型（Type）：string
种类（Kind）：string
值（Value）：hello
-----------------
=== 变量信息 ===
原始值：3.14
类型（Type）：float64
种类（Kind）：float64
值（Value）：3.14
-----------------
=== 变量信息 ===
原始值：[1 2 3]
类型（Type）：
种类（Kind）：slice
值（Value）：[1 2 3]
-----------------
=== 变量信息 ===
原始值：{张三 20}
类型（Type）：struct { Name string; Age int }
种类（Kind）：struct
值（Value）：{张三 20}
-----------------
```
**关键解释**：
- `Type.Name()`：返回类型名（自定义结构体有名称，切片/数组等无名称）；
- `Kind()`：返回底层种类（如`int`、`slice`、`struct`），区分“类型”和“种类”是关键（比如`type MyInt int`，Name是MyInt，Kind是int）；
- `Value.Interface()`：将反射值转回`any`，可通过类型断言还原（如`v.Interface().(int)`）。

#### 示例2：还原反射对象为接口值（法则2）
将反射对象转回原变量类型，核心是`Interface()` + 类型断言：
```go
package main

import (
	"fmt"
	"reflect"
)

func main() {
	var num int = 100

	// 1. 反射获取Value
	v := reflect.ValueOf(num)

	// 2. 转回interface{}
	iv := v.Interface()

	// 3. 类型断言还原为int
	n, ok := iv.(int)
	if ok {
		fmt.Printf("还原后的int值：%d（类型：%T）\n", n, n) // 输出：100（int）
	}

	// 对结构体的还原
	p := struct{ Name string }{"李四"}
	v2 := reflect.ValueOf(p)
	iv2 := v2.Interface()
	p2, ok := iv2.(struct{ Name string })
	if ok {
		fmt.Printf("还原后的结构体：%v（类型：%T）\n", p2, p2) // 输出：{李四}
	}
}
```

#### 示例3：修改反射对象的值（法则3，重点避坑）
新手最容易踩坑的场景：修改反射值必须满足“可设置性”，核心是传递**指针**并通过`Elem()`获取指针指向的原值。

##### 错误示例（不可设置）：
```go
package main

import (
	"fmt"
	"reflect"
)

func main() {
	var num int = 10
	v := reflect.ValueOf(num) // 传递的是num的副本，不是原值

	// 尝试修改：panic: reflect: reflect.Value.SetInt using unaddressable value
	v.SetInt(20)
	fmt.Println(num)
}
```
**错误原因**：`reflect.ValueOf(num)`获取的是num的副本，反射对象指向的是副本（不可寻址），因此不可设置。

##### 正确示例（可设置）：
```go
package main

import (
	"fmt"
	"reflect"
)

func main() {
	var num int = 10
	// 1. 传递指针（reflect.ValueOf(&num)）
	v := reflect.ValueOf(&num)
	// 2. 通过Elem()获取指针指向的原值（可寻址）
	v = v.Elem()

	// 3. 检查是否可设置（可选，但推荐）
	if v.CanSet() {
		v.SetInt(20) // 修改原值
		fmt.Println("修改后num：", num) // 输出：20
	} else {
		fmt.Println("反射对象不可设置")
	}

	// 对结构体字段的修改（注意：字段必须首字母大写，否则不可导出，也不可设置）
	type Person struct {
		Name string // 首字母大写，可导出
		age  int    // 首字母小写，不可导出
	}
	p := Person{Name: "张三", age: 20}
	vp := reflect.ValueOf(&p).Elem()

	// 修改Name字段（可导出，可设置）
	nameField := vp.FieldByName("Name")
	if nameField.CanSet() {
		nameField.SetString("李四")
	}

	// 尝试修改age字段（不可导出，不可设置）
	ageField := vp.FieldByName("age")
	if ageField.CanSet() {
		ageField.SetInt(25)
	} else {
		fmt.Println("age字段不可设置（未导出）")
	}

	fmt.Println("修改后的结构体：", p) // 输出：{李四 20}
}
```
**关键规则（可设置性）**：
1. 反射对象必须指向**原变量的内存地址**（即传递指针，再通过`Elem()`解引用）；
2. 变量必须是**可导出的**（结构体字段首字母大写，否则即使传指针也不可设置）；
3. 可通过`CanSet()`提前判断是否可设置，避免panic。

#### 示例4：遍历结构体（字段、标签、方法）
反射最常用的场景：遍历结构体的字段、解析tag（如JSON标签）、调用方法，是ORM/JSON序列化的核心逻辑。
```go
package main

import (
	"fmt"
	"reflect"
)

// 定义带tag的结构体
type User struct {
	ID   int    `json:"id" desc:"用户ID"`
	Name string `json:"name" desc:"用户名"`
	Age  int    `json:"age" desc:"年龄"`
}

// 给结构体添加方法
func (u User) GetInfo() string {
	return fmt.Sprintf("ID：%d，姓名：%s，年龄：%d", u.ID, u.Name, u.Age)
}

func (u *User) SetAge(newAge int) {
	u.Age = newAge
}

func main() {
	u := User{ID: 1001, Name: "张三", Age: 20}

	// 1. 获取结构体的Type（传指针，避免副本）
	t := reflect.TypeOf(&u).Elem()
	// 2. 获取结构体的Value
	v := reflect.ValueOf(&u).Elem()

	// 遍历结构体字段
	fmt.Println("=== 遍历结构体字段 ===")
	for i := 0; i < t.NumField(); i++ {
		// 获取字段的Type信息
		fieldType := t.Field(i)
		// 获取字段的Value信息
		fieldValue := v.Field(i)

		// 输出字段信息
		fmt.Printf("字段名：%s\n", fieldType.Name)
		fmt.Printf("  类型：%s\n", fieldType.Type)
		fmt.Printf("  值：%v\n", fieldValue.Interface())
		fmt.Printf("  JSON标签：%s\n", fieldType.Tag.Get("json"))
		fmt.Printf("  描述标签：%s\n", fieldType.Tag.Get("desc"))
		fmt.Println("-----------------")
	}

	// 调用结构体的方法
	fmt.Println("=== 调用结构体方法 ===")
	// 方法1：调用值方法（GetInfo）
	// 获取方法：MethodByName(方法名)
	mGetInfo := v.MethodByName("GetInfo")
	// 调用方法：Call(参数列表，[]reflect.Value类型)
	args := []reflect.Value{} // 无参数
	results := mGetInfo.Call(args)
	// 解析返回值
	if len(results) > 0 {
		fmt.Println("GetInfo返回值：", results[0].Interface())
	}

	// 方法2：调用指针方法（SetAge）
	// 注意：调用指针方法需用指向结构体的Value
	mSetAge := v.MethodByName("SetAge")
	// 构造参数（int(25)转为reflect.Value）
	ageArg := []reflect.Value{reflect.ValueOf(25)}
	// 调用方法（无返回值）
	mSetAge.Call(ageArg)
	fmt.Println("调用SetAge后Age：", u.Age) // 输出：25
}
```
**运行结果**：
```
=== 遍历结构体字段 ===
字段名：ID
  类型：int
  值：1001
  JSON标签：id
  描述标签：用户ID
-----------------
字段名：Name
  类型：string
  值：张三
  JSON标签：name
  描述标签：用户名
-----------------
字段名：Age
  类型：int
  值：20
  JSON标签：age
  描述标签：年龄
-----------------
=== 调用结构体方法 ===
GetInfo返回值： ID：1001，姓名：张三，年龄：20
调用SetAge后Age： 25
```
**关键解释**：
- `Type.NumField()`：返回结构体字段数量；
- `Type.Field(i)`：获取第i个字段的类型信息（含tag）；
- `Value.Field(i)`：获取第i个字段的值；
- `Tag.Get("key")`：解析结构体tag（如JSON标签）；
- `Value.MethodByName()`：获取方法，`Call()`调用方法（参数/返回值都是`[]reflect.Value`）。

#### 示例5：反射的实际应用——简易JSON序列化
模拟JSON序列化的核心逻辑，体现反射的价值：
```go
package main

import (
	"encoding/json"
	"fmt"
	"reflect"
	"strconv"
)

// SimpleJSONMarshal 简易JSON序列化（仅支持基础类型和结构体）
func SimpleJSONMarshal(x any) (string, error) {
	v := reflect.ValueOf(x)

	// 根据Kind处理不同类型
	switch v.Kind() {
	case reflect.Int, reflect.Int64:
		return strconv.FormatInt(v.Int(), 10), nil
	case reflect.String:
		return "\"" + v.String() + "\"", nil
	case reflect.Struct:
		// 处理结构体
		var res = "{"
		t := v.Type()
		for i := 0; i < v.NumField(); i++ {
			fieldT := t.Field(i)
			fieldV := v.Field(i)

			// 解析json tag，无tag则用字段名
			jsonKey := fieldT.Tag.Get("json")
			if jsonKey == "" {
				jsonKey = fieldT.Name
			}

			// 递归序列化字段值
			fieldJson, err := SimpleJSONMarshal(fieldV.Interface())
			if err != nil {
				return "", err
			}

			// 拼接键值对
			res += "\"" + jsonKey + "\":" + fieldJson
			if i < v.NumField()-1 {
				res += ","
			}
		}
		res += "}"
		return res, nil
	default:
		return "", fmt.Errorf("不支持的类型：%s", v.Kind())
	}
}

func main() {
	u := User{ID: 1001, Name: "张三", Age: 20}

	// 自定义反射序列化
	jsonStr, err := SimpleJSONMarshal(u)
	if err != nil {
		fmt.Println("序列化失败：", err)
	} else {
		fmt.Println("自定义序列化结果：", jsonStr)
	}

	// 对比标准库json.Marshal
	stdJson, _ := json.Marshal(u)
	fmt.Println("标准库序列化结果：", string(stdJson))
}
```
**运行结果**：
```
自定义序列化结果： {"id":1001,"name":"张三","age":20}
标准库序列化结果： {"id":1001,"name":"张三","age":20}
```
**核心价值**：标准库`encoding/json`的底层就是基于反射实现的——通过反射遍历结构体字段、解析tag、转换值类型，最终拼接成JSON字符串。

### 三、反射的避坑点和最佳实践
#### 1. 避坑点
- **性能开销**：反射是运行时操作，比直接代码慢10~100倍，高频场景（如热点接口）尽量避免；
- **可设置性**：修改值必须传指针+`Elem()`，结构体字段必须首字母大写；
- **类型断言**：反射转回接口值后，必须用类型断言（加`ok`判断），避免panic；
- **Kind vs Type**：区分“种类”和“类型”（如`type MyInt int`，Type是MyInt，Kind是int）；
- **方法调用**：调用指针方法需用指向结构体的Value，值方法可用值/指针Value。

#### 2. 最佳实践
- **尽量不用反射**：能用普通代码实现的，优先不用反射（如普通函数、泛型）；
- **封装反射逻辑**：将反射代码封装成通用函数，避免散落在业务代码中；
- **提前校验**：用`CanSet()`、`NumField()`等提前校验，避免运行时panic；
- **结合泛型**：Go 1.18+泛型可替代部分反射场景（如通用工具函数），性能更好且类型安全。

### 总结
1. 反射的核心是`reflect.Type`（类型信息）和`reflect.Value`（值信息），入口是`reflect.TypeOf()`/`reflect.ValueOf()`；
2. 三大法则：接口值→反射对象→接口值，修改反射值需满足“可设置性”；
3. 核心场景：遍历结构体（解析tag）、调用方法、通用框架（JSON/ORM）；
4. 避坑关键：注意可设置性、性能开销，优先用普通代码/泛型替代反射；
5. 反射的价值：实现“编译期未知类型”的通用逻辑，是框架开发的核心技术，但业务代码需谨慎使用。

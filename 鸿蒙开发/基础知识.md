# ohpm

ohpm是一个类似于npm的仓库，为鸿蒙开发专门搭建，[官方文档](https://ohpm.openharmony.cn/#/cn/help/quickstart)。
ohpm需要在devEco的终端运行，在`oh-package.json5`中添加依赖。

# UI

鸿蒙的UI使用声明式UI，但是其API大部分借鉴的HTML+CSS，因此开发时可参考HTML+CSS的命名来编写加上IDE的提示来猜API。

## UI单位

鸿蒙默认单位是vp，不过后面新出了lpx更适合根据设计稿开发，所有单位如下：

- px: 像素，ppi为5表示宽高为5px共25px（尽量不用，除非绘制1px边框等特殊场景）
- vp: 屏幕像素密度值。和像素是一个比例关系：$px = vp × dpi / 160$ 或 $px = vp × 比例系数(scale)$==（不同设备上的物理宽度差不多，比如都是差不多2cm宽，但是还是略有差异，约 ±0.1cm）==
- fp: 字体像素大小默认情况下与 vp 相同，即默认情况下 1 fp = 1 vp。如果用户在设置中选择了更大的字体，字体的实际显示大小就会在vp的基础上乘以scale系数，即 1 fp = 1 vp \* scale。用于显示文字的页面，如介绍页、隐私页等（字体大小设置，可跟随系统字体设置缩放）
- lpx: 由实际屏幕宽度与设计逻辑宽度（designWidth）的比值决定 $1 lpx = (实际屏幕物理宽度 / designWidth) px$ ==（类似rpx）==

## 断点系统

| 断点类型 | 横向断点 (vp) | 纵向断点 (vp) | 适用设备示例          |
| -------- | ------------- | ------------- | --------------------- |
| xs       | < 320         | < 455         | 小屏设备（如手表）    |
| sm       | 320-599       | 455-719       | 直板手机竖屏          |
| md       | 600-839       | 720-1279      | 折叠屏展开态/平板竖屏 |
| lg       | 840-1079      | 1280-1599     | 平板横屏              |
| xl       | ≥ 1080        | ≥ 1600        | PC/大屏设备           |

    ```ts
    import { px2vp } from '@kit.ArkUI';
    import display from '@kit.DisplayKit';

    // 获取默认屏幕对象
    let displayObj = display.getDefaultDisplaySync();

    // 获取屏幕宽度和高度（单位：px）
    let screenWidthPx = displayObj.width;
    let screenHeightPx = displayObj.height;

    // 将物理像素转换为逻辑像素
    let screenWidthVp = px2vp(screenWidthPx);
    let screenHeightVp = px2vp(screenHeightPx);

    // 判断是否为横屏大屏（xl断点）
    if (screenWidthVp >= 1080 && screenHeightVp < 1600) {
        console.log('大屏横屏设备：采用多列网格布局');
    } else if (screenWidthVp < 600) {
        console.log('小屏设备：使用单列列表布局');
    }
    ```

## UI渲染流程
鸿蒙的UI渲染不是像React那样修改状态后整个struct/build重新走一遍，而是像Vue那样只更新变化的UI元素。

## UI装饰器

[UI装饰器总览](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-decorator-overview)
组件扩展：

- @Builder: 组件内用函数封装的一块UI代码，因为使用普通函数不能像React那样return UI代码，所以需要使用@Builder装饰器来封装。
  相较于@Component封装成一个单独的组件，没有生命周期等，性能开销更低，适合封装只在当前组件内使用的UI代码。
- @BuilderParam: 类似于React的children/vue的slot插槽，用于通过参数往组件内传递UI元素。

    ```ts
    @Component
    struct Card {
      // 使用@BuilderParam装饰器定义一个参数，用于接收外部传入的UI元素。
      @BuilderParam content: () => void
      build() {
        Column() {
          Text("标题")
          this.content()   // 渲染外部传入的 UI
        }
      }
    }

    // 使用Card组件
    Card({
      // 通过子组件定义的@BuilderParam content方法传递UI元素
      content: () => {
        Text("自定义内容")
        Button("按钮")
      }
    })
    ```

- @Param: 接收父组件数据的参数，只能接收数据而不能接收UI元素。
- @Style: 类似于class，封装多个样式为一个函数进行调用。在原生开发中更建议直接将样式通过链式调用写到UI元素上，类似tailwind，而不是像前端那样通过class来封装样式。（不支持传参）

    ```ts
    // 使用@Styles装饰器封装多个样式为一个函数fancy()
    @Styles
    fancy() {
      .height(this.heightValue)
      .backgroundColor(Color.Blue)
      .onClick(() => {
        this.heightValue = 100;
      })
    }

    build() {
      Column() {
        Button('change height')
          .fancy() // 调用fancy函数，设置按钮的样式
      }
      .height('100%')
      .width('100%')
    }
    ```

- @Extend: 用于给指定的组件添加方法来扩展样式。相较于@Styles，这个就只是给某一个组件添加样式而不是通用。（支持传参）

    ```ts
    // 使用@Extend装饰器给Text组件添加方法fancy
    @Extend(Text)
    function fancy() {
      .fontColor(Color.Red)
    }

    // 在fancy的基础上再扩展样式
    @Extend(Text)
    function superFancyText(size: number) { // 支持传参
      .fontSize(size)
      .fancy() // 调用fancy函数，设置字体颜色为红色
    }

    @Entry
    @Component
    struct FancyUse {
      build() {
        Row({ space: 10 }) {
          Text('Fancy')
            .fancy() // 调用fancy函数，设置字体颜色为红色
          Text('Fancy')
            .superFancyText(24) // 调用superFancyText函数，设置字体颜色为红色，字体大小为24
        }
      }
    }
    ```

- stateStyles: 类似css的伪类，包括focused：获焦态、normal：正常态、pressed：按压态、disabled：不可用态、clicked：点击态、selected：选中态。

```ts
@Entry
@Component
struct StateStylesSample {
  @Styles normalStyle() {
    .backgroundColor(Color.Gray)
  }
  build() {
    Column() {
      Button('Button1')
        .stateStyles({ // 使用stateStyles
          focused: {
            .backgroundColor('#ffffeef0')
          },
          pressed: {
            .backgroundColor('#ff707070')
          },
          normal: this.normalStyle, // 通过@Styles配合使用
        })
        .margin(20)
    }.margin('30%')
  }
}
```

- @AnimatableExtend: 用于给指定的组件添加动画效果。有些属性支持动画，可以使用.animateTo()方法来直接实现，有些属性不自带动画支持，就需要使用@AnimatableExtend装饰器来实现。

```ts
// 使用@AnimatableExtend装饰器给Text组件添加方法animatableWidth
@AnimatableExtend(Text)
function animatableWidth(width: number) {
  .width(width)
}

@Entry
@Component
struct AnimatablePropertyText {
  @State textWidth: number = 80;

  build() {
    Column() {
      Text('AnimatableProperty')
        .animatableWidth(this.textWidth) // 调用animatableWidth方法，设置文本宽度为this.textWidth
        .animation({ duration: 2000, curve: Curve.Ease }) // 添加动画效果
      Button('Play')
        .onClick(() => {
          this.textWidth = this.textWidth == 80 ? 160 : 80; // 点击修改textWidth就会触发动画效果
        })
    }.width('100%')
    .padding(10)
  }
}
```

- @Require: 修饰@Param等，要求父组件必须传递该参数。

## 全局状态管理
[AppStorageV2文档](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-new-appstoragev2)
全局状态管理需要使用AppStorageV2, @ObservedV2和@Trace装饰器。@ObservedV2和@Trace是让一个class类具有全局状态管理的能力，而AppStorageV2可以将这个class用于全局状态管理。
```ts
// 数据中心 Sample.ets
@ObservedV2 // 使用@ObservedV2装饰器使Sample类具有UI响应的能力
export class Sample {
  @Trace public p1: number = 0; // 使用@Trace装饰器使p1具有UI响应的能力
  public p2: number = 10; // 不使用@Trace装饰器，p2不会具有UI响应的能力
}
```
```ts
// 首页
import { AppStorageV2 } from '@kit.ArkUI'; // 导入AppStorageV2
import { Sample } from './Sample'; // 导入Sample类

@Entry
@ComponentV2
struct PageOne {
  // 使用AppStorageV2.connect()方法将Sample类用于全局状态管理
  // 会根据类名创建一个名为Sample的键值对；如果Sample已存在，则不会创建而直接返回
  @Local prop: Sample = AppStorageV2.connect(Sample, () => new Sample())!; 
  pageStack: NavPathStack = new NavPathStack(); // 创建一个NavPathStack对象，用于管理应用中的页面栈

  build() {
    Navigation(this.pageStack) { // 使用Navigation组件，将pageStack作为参数传递
      Column() {
        Button('Go to pageTwo')
          .onClick(() => {
            // 使用pageStack跳转页面。第二个参数可以传参，第三个参数用于接收页面返回的参数
            this.pageStack.pushPathByName('PageTwo', '这是参数', (info) => {
              console.log(info.result['msg'])
            });
          })

        Button('PageOne connect the key Sample')
          .onClick(() => {
            // 上面已经创建了Sample这个key，所以实际上是使用Sample
            this.prop = AppStorageV2.connect(Sample, 'Sample', () => new Sample())!;
          })

        Text(`PageOne add 1 to prop.p1: ${this.prop.p1}`)
          .fontSize(30)
          .onClick(() => {
            this.prop.p1++;
          })
      }
    }
  }
}
```
```ts
// 页面 PageTwo.ets
import { AppStorageV2 } from '@kit.ArkUI';
import { Sample } from './Sample';

@Builder
export function PageTwoBuilder() {
  PageTwo()
}

@ComponentV2
struct PageTwo {
  @Local prop: Sample = AppStorageV2.connect(Sample, () => new Sample())!; // 同样的连接上Sample类
  @Local msg: string = '';
  pathStack: NavPathStack = new NavPathStack(); // 创建了一个新的栈对象。这里赋值是容错，实际会用下面的onReady方法赋值

  build() {
    NavDestination() { // 使用NavDestination创建子页面
      Column() {
        Button('PageTwo connect the key Sample1')
          .onClick(() => {
            // 创建了另一个Sample1为key的store，和Sample是不同的store
            this.prop = AppStorageV2.connect(Sample, 'Sample1', () => new Sample())!;
          })

        // 如果this.Props是Sample则和首页的数据相同
        // 如果点击了上面的按钮则会切换为Sample1的数据
        Text(`PageTwo add 1 to prop.p1: ${this.prop.p1}`)
          .fontSize(30)
          .onClick(() => {
            this.prop.p1++; // 点击后如果this.Props是Sample，则会影响首页的数据
          })

        Button('返回带传参')
          .onClick(() => {
            this.pathStack.pop({ msg: '返回带参'}) // 使用pop方法返回上一页，第二个参数可以传参
          })
      }
    }
    .onReady((context: NavDestinationContext) => {
      this.msg = context.pathInfo.param as string; // 通过context.pathInfo.param获取到页面跳转时传递的参数
      this.pathStack = context.pathStack; // 这里取出来赋值才是同一个pathStack对象
    })
  }
}
```

# 静态资源

静态资源主要放在`entry\src\main\resources\base`目录中，使用`$r(app.media.logo)`来引入`media/logo.png`文件。
资源目录中不能同时有`logo.png`和`logo.jpg`两个同名但扩展名不同的文件，不支持通过扩展名区分。

# 生命周期
==这里是使用@Entry装饰的页面具有的生命周期，如果使用Navigation跳转的实际上是打开一个组件，生命周期需要看Navigation相关说明。==
- aboutToAppear: 创建自定义组件的新实例后，在执行其build函数之前执行。
- build: 执行组件渲染。
- onDidBuild: **首次渲染**触发的build函数执行完成之后回调该接口，后续组件重新渲染将不回调该接口。开发者可以在这个阶段实现埋点数据上报等不影响实际UI的功能。
- aboutToDisappear: 在自定义组件销毁之前执行（如if判断组件是否显示）。不允许在aboutToDisappear函数中改变状态变量。不建议在这里面使用 async await。

创建组件会先执行父组件的生命周期，走完onDidBuild后才执行子组件的aboutToAppear。
删除组件也是先执行父组件的aboutToDisappear后再执行子组件的aboutToDisappear。

# 路由

## Navigation
[Navigation文档](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-navigation-navigation)
Navigation实际上是控制组件的显示/隐藏来实现类似路由的跳转。
Navigation主要包括Navigation、NavDestination、NavPathStack等。
- Navigation: 用于应用入口页面，整个应用通常只有一个Navigation组件。
- NavDestination: 用于应用的其它页面，实际上使用Navigation后应用打开页面就是加载一个组件，而不是真正的路由跳转。
- NavPathStack: 用于管理应用中的页面栈，可以控制子页面的切换等。（具有页面跳转方法）

使用Navigation后，新增页面需要配置routerMap进行注册。
[使用实例参考全局状态管理](#全局状态管理)

- Navigation还可以通过链式调用添加tabbar、导航等，不过估计自己写会更好一些。
- 通过NavDestination的链式调用实现生命周期方法。[生命周期](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-navigation-navigation#页面生命周期)

## @ohos.router
@ohos.router是真正的路由跳转。但是因为性能、动效等因素，官方推荐使用Navigation来实现路由。

# 渲染控制
[渲染控制文档](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-rendering-control-overview)
在build方法中提供了渲染相关的方法，如ForEach, LazyForEach等。
- if/else：条件渲染：使用if/else语句来根据条件渲染不同的组件。
- ForEach：循环渲染：使用ForEach来根据数组或列表渲染组件。
- LazyForEach：懒加载渲染：当LazyForEach中的组件滚动到可视区域内时创建组件，滚动出可视区域会销毁并回收组件。==（推荐使用Repeat）==
- Repeat：V2新增的懒加载组件，懒加载更推荐使用此组件。

# 布局
[布局文档](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-layout-development-overview)
- 线性布局(Row/Column)：类似flex的flex-direction，性能较高。
- 叠层布局(Stack): 类似于`position: relative`和`position: absolute`，但是子元素默认居中，可通过`.align`来调整对齐方式。
- 弹性布局(Flex)：类似于Web的flex布局，有性能问题，慎用。
  |​特性|​Flex布局|​Row/Column布局​|
  |---|---|---|
  |​布局机制​|	动态弹性计算，支持二次布局（重新分配空间）|	单次线性排列，无二次布局|
  |​方向控制​|	支持水平（Row）、垂直（Column）及反向排列|	Row仅水平，Column仅垂直|
  |​子组件控制​|	支持flexGrow、flexShrink、flexBasis动态分配空间|	仅支持layoutWeight按比例分配空间|
  |​性能表现​|	较低（二次布局增加计算开销）|	较高（单次布局完成）|
- 相对布局(RelativeContainer)：也类似于`position: relative`和`position: absolute`，但是比Stack布局更灵活，也更复杂。
- 栅格布局(GridRow/GridCol)：类似于CSS Grid + Bootstrap 栅格系统。
- 选项卡(Tabs)：用于在多个选项卡之间切换。有`aboutToAppear`和`aboutToDisappear`生命周期方法。

# 列表和网格
[列表和网格文档](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-list-grid-development-overview)
- 列表(List)：List的子组件必须是ListItemGroup或ListItem。类似ScrollView。
- 网格(Grid/GridItem)：Grid的子组件必须是GridItem组件。优点类似于table，可以合并单元格之类。
- 瀑布流(WaterFlow)：WaterFlow的子组件必须是FlowItem组件。
